## 第 0 步：项目全景 —— 先看地图

读代码前，先搞清三件事：**这个系统解决什么问题、由哪几大块组成、数据怎么流动。**

### 0.1 这个项目是干嘛的？

**SmartTicket-Agent 是一个"智能工单系统"**。传统场景里，用户报故障 → 客服手动填工单 → 手动分类 → 手动派给工程师 → 解决后知识浪费掉。这个项目用**大模型 + 多智能体 + 混合检索**把整条流水线自动化了：

- 用户说人话（比如"我服务器一直 502 报错"），系统自动**识别意图**、**抽取关键信息**、**创建工单**、**自动派单**；
- 知识库支持**关键词 + 语义**双路检索，帮用户和工程师快速找到历史解决方案；
- 工单解决后，自动**总结成知识条目**沉淀进库，越用越聪明。

### 0.2 技术选型（都贴"国内可用"标签）

| 组件 | 选型 | 说明 |
|---|---|---|
| 大模型 | DeepSeek（`deepseek-chat`） | 国内直连 API |
| 向量化 Embedding | 阿里云 DashScope `text-embedding-v3`（1024 维） | 把文字变成数字向量 |
| 重排序 Rerank | 阿里云 DashScope `gte-rerank-v2` | 对检索结果二次精排 |
| 编排框架 | LangChain + LangGraph | 用"图"的方式编排多个 Agent |
| 搜索 | Elasticsearch 8.11 + IK 中文分词 | 全文检索 + 向量检索双能力 |
| 消息队列 | Kafka 3.7（KRaft 模式，免 Zookeeper） | 削峰、异步 |
| 前端 | Streamlit | 纯 Python 写界面 |
| 部署 | Docker Compose | 一键起 4 个服务 |

### 0.3 系统架构（数据怎么流）

```

用户提问 ──► 意图识别Agent ──► 槽位填充Agent ──► 创建工单 ──► 智能派单Agent
                  │                                    │

                  │   Query改写 → BM25+向量 → RRF融合 → Rerank精排
```

### 0.4 阅读前，先理解 3 个贯穿全文的概念

1. **环境变量（env）**：API Key 这类秘密信息不能写死在代码里，而是放在 `.env` 文件里，代码运行时用 `os.getenv("XXX")` 读取。所以你会反复看到 `os.getenv("LLM_MODEL", "deepseek-chat")` 这种写法——第二个参数是"取不到时的默认值"。

2. **依赖注入**：很多类（比如 `TicketTools`）在构造函数里接收 `es_client`、`search_pipeline` 等参数，而不是自己 `new` 一个。好处是：测试时可以塞假对象，生产时可以塞真对象，代码更灵活。你会看到 `__init__(self, es_client=None, ...)` 这种"可选依赖"写法，传了就用，没传就退化成纯内存模式。

3. **兜底（fallback）思想**：整个项目的代码风格是"能用就用，不能用也不崩"。几乎每个外部调用（LLM、ES、Kafka、Embedding）都被 `try/except` 包住，失败时返回一个降级结果。这是生产级代码的典型特征，读的时候留意这种模式。

## 第 1 步：`configs/__init__.py` —— 全局配置加载器（整个项目的地基）

**角色**：这是全项目最底层的模块。它负责两件事：① 读取 `.env` 里的环境变量；② 读取 `configs/` 目录下的 YAML 配置文件，并支持在配置里用 `${变量名:-默认值}` 引用环境变量。其他模块要么直接 `import configs` 拿配置，要么自己用 `os.getenv` 读环境变量——但它不依赖项目里任何其他模块，所以排第一。

**几个关键点先扫一眼，再读代码**：
- `ROOT_DIR = Path(__file__).parent.parent`：用"当前文件所在目录的上一级"定位项目根目录，这样不管从哪个目录运行脚本都能找到配置文件。
- `load_yaml_config`：读 YAML 时，先用正则把 `${VAR:-default}` 替换成环境变量的真实值，再交给 `yaml.safe_load` 解析。这就是配置里能写 `${ES_HOST:-http://localhost:9200}` 的原因。
- 文件底部 `ES_CONFIG`、`KAFKA_CONFIG`、`AGENT_CONFIG` 三个变量在**导入时立即执行**——意味着只要 `import configs`，三个 YAML 就会被解析好。

```python
"""
全局配置加载模块
从 .env 和 configs/*.yaml 加载配置，供所有模块使用
"""
import os
from pathlib import Path
from dotenv import load_dotenv
import yaml

# 项目根目录
ROOT_DIR = Path(__file__).parent.parent

# 加载 .env
load_dotenv(ROOT_DIR / ".env")


def load_yaml_config(filename: str) -> dict:
    """加载 YAML 配置文件，支持环境变量替换"""
    config_path = ROOT_DIR / "configs" / filename
    with open(config_path, "r", encoding="utf-8") as f:
        raw = f.read()

    # 简单环境变量替换：${VAR:-default}
    import re
    def replace_env(match):
        var_name = match.group(1)
        default = match.group(3) if match.group(3) else ""
        return os.getenv(var_name, default)

    raw = re.sub(r'\$\{([^}:]+)(:-([^}]*))?\}', replace_env, raw)
    return yaml.safe_load(raw)


# 加载所有配置
ES_CONFIG = load_yaml_config("es_config.yaml")
KAFKA_CONFIG = load_yaml_config("kafka_config.yaml")
AGENT_CONFIG = load_yaml_config("agent_config.yaml")

# 常用快捷访问
ES_HOST = os.getenv("ES_HOST", "http://localhost:9200")
KAFKA_BOOTSTRAP = os.getenv("KAFKA_BOOTSTRAP", "localhost:9092")
DEEPSEEK_API_KEY = os.getenv("DEEPSEEK_API_KEY", "")
DASHSCOPE_API_KEY = os.getenv("DASHSCOPE_API_KEY", "")
LLM_MODEL = os.getenv("LLM_MODEL", "deepseek-chat")
LLM_BASE_URL = os.getenv("LLM_BASE_URL", "https://api.deepseek.com")
```

**读完你应掌握**：
- 为什么 `ROOT_DIR` 要用 `Path(__file__).parent.parent`（而不是写死绝对路径）——为了可移植。
- `${VAR:-default}` 这个语法在整个项目的 YAML 配置里反复出现，含义是"优先用环境变量 VAR，没有就用 default"。
- 这个文件是"副作用式"模块：`import` 它的那一刻就完成了配置加载，不需要你手动调用任何函数。

## 第 3 步：`preprocess/cleaner.py` —— 文本清洗工具（最底层的纯工具类）

**角色**：用户输入往往是脏的——带表情、URL、重复标点、控制字符。这些"噪声"会干扰后续的规则匹配和 LLM 抽取。`TicketCleaner` 就是一台"文本洗衣机"，把脏文本洗成干净文本。

**为什么排这么靠前**：它只 `import re` 和 `unicodedata`（Python 标准库），不依赖项目里任何东西，是纯粹的、可独立测试的工具类。第 6 步的实体抽取器会调它。

**设计要点**：
- 全是 `@classmethod`，**不用实例化**，直接 `TicketCleaner.clean(text)` 调用——因为它不保存任何状态，天然适合做成静态工具。
- 用**预编译的正则**（类属性 `EMOJI_PATTERN`、`URL_PATTERN`、`REPEAT_PATTERN`）而不是在函数里现写——正则编译很耗时，提前编译一次、反复复用是性能优化。

```python
"""
工单文本清洗模块
负责：去除特殊字符、表情符号、URL、重复标点等无关信息
"""
import re
import unicodedata


class TicketCleaner:
    """工单文本预清洗器"""

    # 表情符号正则
    EMOJI_PATTERN = re.compile(
        "["
        "\U0001F600-\U0001F64F"  # emoticons
        "\U0001F300-\U0001F5FF"  # symbols & pictographs
        "\U0001F680-\U0001F6FF"  # transport & map symbols
        "\U0001F1E0-\U0001F1FF"  # flags
        "\U0001F900-\U0001F9FF"  # supplemental symbols
        "\U0001FA70-\U0001FAFF"  # symbols extended-A
        "\U00002702-\U000027B0"  # dingbats
        "\U00002600-\U000026FF"  # misc symbols
        "\U0000FE00-\U0000FE0F"  # variation selectors
        "\U0000200D"             # zero width joiner
        "]+",
        flags=re.UNICODE,
    )

    # URL 匹配
    URL_PATTERN = re.compile(
        r'https?://\S+|www\.\S+|\S+\.\S+/\S+'
    )

    # 连续重复字符（如 "！！！！" → "！"）
    REPEAT_PATTERN = re.compile(r'(.)\1{2,}')

    @classmethod
    def clean(cls, text: str) -> str:
        """
        清洗工单文本
        1. 去除表情符号
        2. 去除 URL
        3. 去除特殊控制字符
        4. 合并连续重复标点
        5. 规范化空白字符
        """
        if not text:
            return ""

        # 1. 去除表情
        text = cls.EMOJI_PATTERN.sub("", text)

        # 2. 去除 URL
        text = cls.URL_PATTERN.sub("", text)

        # 3. 去除控制字符（保留中文、英文、数字、常见标点）
        text = "".join(
            ch for ch in text
            if unicodedata.category(ch)[0] != "C" or ch in ("\n", "\t")
        )

        # 4. 合并连续重复标点（保留最多2个）
        text = cls.REPEAT_PATTERN.sub(r"\1\1", text)

        # 5. 规范化空白
        text = re.sub(r"\s+", " ", text).strip()

        return text

    @classmethod
    def extract_error_codes(cls, text: str) -> list:
        """从文本中提取错误码（如 502, 404, ERROR-001 等）"""
        patterns = [
            r'\b\d{3,4}\s*(?:error|错误|报错)\b',           # 502错误
            r'\b(?:error|错误|报错)\s*[:\-]?\s*\d{3,4}\b',  # 错误:502
            r'\b[A-Z]+-\d{2,}\b',                            # ERROR-001
        ]
        codes = []
        for p in patterns:
            codes.extend(re.findall(p, text, re.IGNORECASE))
        return list(set(codes))

    @classmethod
    def extract_product_model(cls, text: str) -> str:
        """提取产品型号（如 手环X1, iPhone15, Server-R740）"""
        pattern = r'[\u4e00-\u9fa5A-Za-z]+[A-Za-z0-9]+[-]?[A-Za-z0-9]+'
        matches = re.findall(pattern, text)
        # 过滤太短的匹配
        return [m for m in matches if len(m) >= 3][0] if matches else ""
```

**读完你应掌握**：
- `clean()` 的五步流水线：去表情 → 去 URL → 去控制字符 → 合并重复标点 → 规范化空白。
- `unicodedata.category(ch)[0] == "C"` 判断"控制字符"的技巧（C 开头 = 控制类，但保留换行和 Tab）。
- `extract_error_codes()` 用三种正则组合抓"502错误 / 错误:502 / ERROR-001"这类错误码，`set()` 去重。
- `extract_product_model()` 抓"手环X1 / iPhone15 / Server-R740"这类产品型号。

## 第 4 步：`preprocess/nlp_classifier.py` —— 规则引擎（最快最省的分流）

**角色**：这是"规则分流"的核心。约 60% 的简单工单（登录、网络、设备、系统、财务五大类）能用关键词 + 正则直接判断，**不用花钱调 LLM**。规则引擎就是干这个的。

**为什么排在 LLM 抽取之前**：它同样是纯规则、零外部依赖，而且成本最低（不调 API）。整个系统的设计哲学是"**能上规则就不用 LLM**"——第 9 步的 Kafka 路由器和第 21 步的派单 Agent 都贯彻了这个思想。

**设计要点**：
- `RULES` 字典是"规则表"：每个类别配 `keywords`（关键词列表）、`patterns`（正则列表）、`skill_group`（对应技能组）、`default_priority`（默认优先级）。**数据驱动**——以后加新类别，只改这个表，不改 `match` 逻辑。
- `match()` 对每类算一个 0~1 的分数，取最高分的那类；分数 ≥ 0.6 才算"命中"。
- `_calculate_score()` 的评分策略：每个关键词命中 +0.3 分（封顶 0.7），每个正则命中 +0.4 分（封顶 0.5）。这是"模糊匹配置信度"的简化实现。
- `_detect_priority()` 用"急/紧急/立即/马上…"判断高优先级，"不急/有空…"判断低优先级，否则用类别默认值。

```python
"""
规则引擎：工单快速分流
通过关键词/正则/条件匹配，快速路由约60%的简单工单，降低 LLM 调用成本
"""
import re
import logging
from typing import Optional

logger = logging.getLogger(__name__)


class RuleEngine:
    """工单规则过滤引擎"""

    # 规则定义：类别 → (关键词列表, 正则模式列表)
    RULES = {
        "登录问题": {
            "keywords": ["密码", "登录", "登不上", "账户", "认证", "忘记密码", "重置密码"],
            "patterns": [r"密码.{0,5}(错误|忘记|不对)", r"(登录|登陆).{0,5}(失败|不了)"],
            "skill_group": "IT支持组",
            "default_priority": "中",
        },
        "网络问题": {
            "keywords": ["网络", "连不上", "断网", "wifi", "WiFi", "DNS", "IP", "ping不通", "网络异常"],
            "patterns": [r"网络.{0,5}(异常|断开|慢)", r"(连接|访问).{0,5}(失败|超时)"],
            "skill_group": "IT支持组",
            "default_priority": "中",
        },
        "设备故障": {
            "keywords": ["死机", "蓝屏", "重启", "卡顿", "黑屏", "花屏", "无法开机", "硬件"],
            "patterns": [r"(设备|电脑|服务器).{0,5}(死机|蓝屏|重启|卡顿)"],
            "skill_group": "维修工程师",
            "default_priority": "高",
        },
        "系统故障": {
            "keywords": ["报错", "错误", "崩溃", "异常", "500", "502", "503", "404", "超时"],
            "patterns": [r"(服务器|系统|接口).{0,5}(报错|错误|崩溃)", r"\d{3}\s*(error|错误|报错)"],
            "skill_group": "IT支持组",
            "default_priority": "高",
        },
        "财务问题": {
            "keywords": ["退款", "金额", "支付", "账单", "发票", "扣费", "充值"],
            "patterns": [r"(退款|支付|账单).{0,5}(问题|异常|疑问)"],
            "skill_group": "财务组",
            "default_priority": "中",
        },
    }

    # 紧急程度关键词
    URGENCY_KEYWORDS = {
        "高": ["急", "紧急", "立即", "马上", "尽快", "严重", "全部", "所有", "无法工作", "生产环境"],
        "低": ["不急", "有空", "方便时", "建议", "优化"],
    }

    def match(self, text: str) -> dict:
        """
        规则匹配
        返回: {
            "matched": bool,          # 是否命中
            "category": str,          # 问题类别
            "confidence": float,      # 置信度
            "skill_group": str,       # 技能组
            "priority": str,          # 优先级
            "match_details": dict,    # 匹配详情
        }
        """
        if not text:
            return self._no_match()

        best_match = None
        best_score = 0.0

        for category, rule in self.RULES.items():
            score = self._calculate_score(text, rule)
            if score > best_score:
                best_score = score
                best_match = {
                    "matched": score >= 0.6,  # 阈值 0.6
                    "category": category,
                    "confidence": min(score, 1.0),
                    "skill_group": rule["skill_group"],
                    "priority": self._detect_priority(text, rule["default_priority"]),
                    "match_details": {"score": score},
                }

        return best_match if best_match else self._no_match()

    def _calculate_score(self, text: str, rule: dict) -> float:
        """计算文本与规则的匹配分数"""
        score = 0.0

        # 关键词匹配（每个关键词 0.3 分，最多 0.7）
        keyword_hits = sum(1 for kw in rule["keywords"] if kw in text)
        score += min(keyword_hits * 0.3, 0.7)

        # 正则匹配（每个模式 0.4 分，最多 0.5）
        pattern_hits = sum(1 for p in rule["patterns"] if re.search(p, text))
        score += min(pattern_hits * 0.4, 0.5)

        return score

    def _detect_priority(self, text: str, default: str) -> str:
        """检测紧急程度"""
        for urgency, keywords in self.URGENCY_KEYWORDS.items():
            if any(kw in text for kw in keywords):
                return urgency
        return default

    def _no_match(self) -> dict:
        """未命中规则"""
        return {
            "matched": False,
            "category": "unknown",
            "confidence": 0.0,
            "skill_group": None,
            "priority": None,
            "match_details": {},
        }
```

**读完你应掌握**：
- 规则引擎 = "规则表（数据）+ 打分函数（逻辑）"的分离。
- 分数阈值（0.6 命中、0.8 高置信度）是这个模块对外的"契约"，后面第 9 步会用到 0.8 这个值。
- `_no_match()` 返回一个统一结构的"未命中"结果，避免调用方做空值判断——所有分支返回结构一致，是防御式编程的好习惯。

## 第 5 步：`preprocess/entity_extraction/prompt_templates.py` —— LLM 提示词模板

**角色**：规则引擎搞不定的（语义模糊、新问题），交给大模型。跟大模型对话需要"提示词（Prompt）"。这个文件把提示词抽成**字符串常量**，集中管理，而不是散落在各处。

**设计要点**：
- 三个模板对应三种 LLM 任务：`ENTITY_EXTRACTION_PROMPT`（抽实体）、`SLOT_SUPPLEMENT_PROMPT`（追问补槽位）、`INTENT_CLASSIFY_PROMPT`（意图分类）。
- 模板里的 `{problem_types}`、`{ticket_text}`、`{user_input}` 是 **`.format()` 的占位符**，调用方用 `.format(problem_types=..., ticket_text=...)` 填空。
- 提示词里要求 LLM"**严格输出 JSON**"，并且给出了 JSON 的骨架（`{{` 在 `.format` 里会被转义成单个 `{`）。为什么要 JSON？因为程序要**解析** LLM 的返回结果，JSON 是最容易解析的格式。
- 每个字段都要求带 `confidence`（置信度），这是后面判断"要不要追问用户"的依据。

## 第 6 步：`preprocess/entity_extraction/extractor.py` —— 实体抽取器（清洗 + Prompt 的组装车间）

**角色**：把第 3 步的清洗器和第 5 步的 Prompt 模板**组装**起来，走完"清洗 → LLM 抽取 → 置信度判断 → 必要时追问"的完整流程。这是第一个"有外部依赖（调 LLM API）"的模块。

**为什么排在这里**：它 `import` 了第 3 步的 `TicketCleaner` 和第 5 步的 prompt 模板，所以必须在这两步之后读。同时它引入了本项目第一个 LLM 客户端的标准写法（后面几乎所有 Agent 都复制这个模式）。

**设计要点**：
- **LLM 客户端标准写法**（`__init__` 里）：用 `ChatOpenAI`（LangChain 对 OpenAI 兼容接口的封装）指向 DeepSeek，参数全部从环境变量读，带默认值。`base_url` 指向 `https://api.deepseek.com`——DeepSeek 的接口是 OpenAI 兼容的，所以能用 `ChatOpenAI` 调它，这是省钱的关键技巧。
- `extract()` 三步：① `TicketCleaner.clean` 清洗 + 抽错误码；② 用模板生成 Prompt 调 LLM；③ 若 LLM 抽取失败，走 `_fallback_extract` 规则兜底。**注意**：错误码优先用正则抽的结果，LLM 没抽到就补上——"确定性规则优先，LLM 兜底"。
- `check_completeness()`：检查必填字段（problem_type、description）是否缺失、置信度是否 ≥ 0.7，不满足就生成追问消息。**置信度低 = 没把握 = 得再问用户**，这是槽位填充的雏形。
- `_parse_json()`：LLM 可能输出 ```json {...}``` 代码块，也可能直接输出裸 JSON，还可能带解释文字。这个函数用正则先把 JSON 对象"抠"出来再 `json.loads`，抠不出来就返回空字典。**这个解析函数在后续 7、8 个文件里几乎一模一样地重复出现**——是本项目最典型的复用模式（虽然有重复，但胜在每处都自包含、不互相耦合）。
- `_fallback_extract()`：LLM 挂了的兜底——退化成关键词匹配，置信度给 0.6 这种"偏低但不为 0"的值。

```python
"""
基于 DeepSeek 大模型的工单实体抽取模块
通过 LangChain 结构化输出提取关键实体
"""
import json
import os
import logging
from typing import Optional

from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage, SystemMessage

from preprocess.cleaner import TicketCleaner
from preprocess.entity_extraction.prompt_templates import (
    ENTITY_EXTRACTION_PROMPT,
    SLOT_SUPPLEMENT_PROMPT,
)

logger = logging.getLogger(__name__)

# 问题类型枚举
PROBLEM_TYPES = ["登录问题", "系统故障", "网络异常", "设备故障", "财务问题", "其他"]


class EntityExtractor:
    """基于 DeepSeek 的工单实体抽取器"""

    def __init__(self):
        self.llm = ChatOpenAI(
            model=os.getenv("LLM_MODEL", "deepseek-chat"),
            base_url=os.getenv("LLM_BASE_URL", "https://api.deepseek.com"),
            api_key=os.getenv("DEEPSEEK_API_KEY"),
            temperature=0.1,
            max_tokens=2048,
        )
        self.confidence_threshold = 0.7

    def extract(self, raw_text: str) -> dict:
        """
        从原始工单文本中提取结构化实体
        流程：清洗 → LLM抽取 → 置信度判断
        """
        # Step 1: 文本清洗
        cleaned_text = TicketCleaner.clean(raw_text)
        error_codes = TicketCleaner.extract_error_codes(raw_text)

        # Step 2: LLM 结构化抽取
        prompt = ENTITY_EXTRACTION_PROMPT.format(
            problem_types="、".join(PROBLEM_TYPES),
            ticket_text=cleaned_text,
        )

        try:
            response = self.llm.invoke([HumanMessage(content=prompt)])
            result = self._parse_json(response.content)
        except Exception as e:
            logger.error(f"LLM 实体抽取失败: {e}")
            result = self._fallback_extract(cleaned_text)

        # Step 3: 补充错误码
        if error_codes and not result.get("error_code"):
            result["error_code"] = error_codes[0]

        result["raw_text"] = raw_text
        result["cleaned_text"] = cleaned_text

        return result

    def check_completeness(self, extracted: dict) -> dict:
        """
        检查抽取结果的完整性
        返回：{"complete": bool, "missing_slots": [...], "follow_up_question": str or None}
        """
        missing = []

        # 检查必填字段
        if not extracted.get("problem_type"):
            missing.append("problem_type（问题类型）")
        elif extracted.get("problem_type_confidence", 1.0) < self.confidence_threshold:
            missing.append(f"problem_type（问题类型，当前置信度{extracted['problem_type_confidence']}）")

        if not extracted.get("description"):
            missing.append("description（问题描述）")
        elif extracted.get("description_confidence", 1.0) < self.confidence_threshold:
            missing.append(f"description（问题描述，当前置信度{extracted['description_confidence']}）")

        if not extracted.get("urgency"):
            missing.append("urgency（紧急程度）")

        if not missing:
            return {"complete": True, "missing_slots": [], "follow_up_question": None}

        # 生成追问
        follow_up = self._generate_follow_up(extracted, missing)

        return {
            "complete": False,
            "missing_slots": missing,
            "follow_up_question": follow_up,
        }

    def _generate_follow_up(self, extracted: dict, missing: list) -> str:
        """生成追问消息"""
        prompt = SLOT_SUPPLEMENT_PROMPT.format(
            extracted_info=json.dumps(extracted, ensure_ascii=False, indent=2),
            missing_slots="\n".join(f"- {s}" for s in missing),
        )
        try:
            response = self.llm.invoke([HumanMessage(content=prompt)])
            return response.content
        except Exception as e:
            logger.error(f"生成追问失败: {e}")
            return f"请补充以下信息：{', '.join(missing)}"

    def _parse_json(self, text: str) -> dict:
        """从 LLM 输出中解析 JSON"""
        # 尝试提取 ```json ... ``` 代码块
        import re
        json_match = re.search(r'```(?:json)?\s*(\{.*?\})\s*```', text, re.DOTALL)
        if json_match:
            text = json_match.group(1)
        else:
            # 尝试直接找 JSON 对象
            json_match = re.search(r'\{.*\}', text, re.DOTALL)
            if json_match:
                text = json_match.group(0)

        try:
            return json.loads(text)
        except json.JSONDecodeError:
            logger.warning(f"JSON 解析失败，原文: {text[:200]}")
            return {}

    def _fallback_extract(self, text: str) -> dict:
        """当 LLM 调用失败时的简单规则抽取"""
        result = {
            "problem_type": None,
            "description": text[:200],
            "urgency": None,
        }

        # 简单关键词匹配
        keyword_map = {
            "登录问题": ["密码", "登录", "登不上", "账户"],
            "网络异常": ["网络", "断网", "连不上", "wifi"],
            "设备故障": ["死机", "蓝屏", "重启", "卡顿"],
            "系统故障": ["报错", "错误", "崩溃", "异常"],
            "财务问题": ["退款", "金额", "支付", "账单"],
        }
        for ptype, keywords in keyword_map.items():
            if any(kw in text for kw in keywords):
                result["problem_type"] = ptype
                result["problem_type_confidence"] = 0.6
                break

        # 紧急程度判断
        if any(w in text for w in ["急", "紧急", "立即", "马上", "马上"]):
            result["urgency"] = "高"
            result["urgency_confidence"] = 0.7
        else:
            result["urgency"] = "中"
            result["urgency_confidence"] = 0.5

        return result
```

## 第 7 步：`data/ingestion/embedding_service.py` —— 向量化服务客户端

**角色**：**Embedding（向量化）** 是把一段文字变成一串数字（本项目 1024 维的浮点数向量）。语义相近的句子，向量在空间里也相近——这是"语义检索"的地基。这个文件封装阿里云 DashScope 的 `text-embedding-v3` 调用。

**为什么排这里**：它是基础设施客户端，被第 8 步（入库脚本）和第 12 步（向量检索器）依赖。读懂它，才能读懂"向量是怎么生成、怎么用"的。

**设计要点**：
- `DashScopeEmbedding` 读环境变量拿模型名/Key/维度，`dashscope.api_key = self.api_key` 是 DashScope SDK 的全局设置方式。
- `embed_text()`：单条文本 → 调 `TextEmbedding.call` → 从响应里取 `output["embeddings"][0]["embedding"]`。
- **失败返回零向量**（`[0.0] * self.dims`）而不是抛异常——这是本项目的兜底哲学。代价是"失败静默"，好处是上层检索流程不会因一条 embedding 失败而崩溃。
- `embed_batch()`：DashScope 单次最多 25 条，所以按 25 分片循环；每片失败也只补零向量，保证"输入 N 条、输出 N 条"数量对齐。

```python
"""
DashScope Embedding 服务封装
使用阿里云 text-embedding-v3 模型，国内直连，替代 BGE-M3
"""
import os
import logging
from typing import Union

import dashscope
from dashscope import TextEmbedding

logger = logging.getLogger(__name__)


class DashScopeEmbedding:
    """阿里云 DashScope Embedding 服务"""

    def __init__(self, model: str = None):
        self.model = model or os.getenv("EMBEDDING_MODEL", "text-embedding-v3")
        self.api_key = os.getenv("DASHSCOPE_API_KEY", "")
        self.dims = int(os.getenv("VECTOR_DIMS", "1024"))
        dashscope.api_key = self.api_key

    def embed_text(self, text: str) -> list[float]:
        """单条文本向量化"""
        try:
            resp = TextEmbedding.call(
                model=self.model,
                input=text,
                dimension=self.dims,
            )
            if resp.status_code == 200:
                return resp.output["embeddings"][0]["embedding"]
            else:
                logger.error(f"Embedding 调用失败: {resp.code} - {resp.message}")
                return [0.0] * self.dims
        except Exception as e:
            logger.error(f"Embedding 异常: {e}")
            return [0.0] * self.dims

    def embed_batch(self, texts: list[str]) -> list[list[float]]:
        """批量文本向量化（DashScope 单次最多 25 条）"""
        all_embeddings = []
        batch_size = 25

        for i in range(0, len(texts), batch_size):
            batch = texts[i:i + batch_size]
            try:
                resp = TextEmbedding.call(
                    model=self.model,
                    input=batch,
                    dimension=self.dims,
                )
                if resp.status_code == 200:
                    batch_embeddings = [item["embedding"] for item in resp.output["embeddings"]]
                    all_embeddings.extend(batch_embeddings)
                else:
                    logger.error(f"批量 Embedding 失败: {resp.code}")
                    all_embeddings.extend([[0.0] * self.dims] * len(batch))
            except Exception as e:
                logger.error(f"批量 Embedding 异常: {e}")
                all_embeddings.extend([[0.0] * self.dims] * len(batch))

        return all_embeddings
```

**读完你应掌握**：
- Embedding 的输入输出：文本（或文本列表）→ 1024 维向量。
- "失败返回零向量"这种降级策略——宁可检索结果差一点，也不能让流程崩掉。
- 批量调用要按服务商上限分片（25 条/次）。

## 第 8 步：`data/ingestion/ingest_docs.py` —— ES 建索引 + 数据入库脚本

**角色**：Elasticsearch（简称 ES）是本项目的"数据库 + 搜索引擎"。这个脚本负责：① 创建三个索引（tickets / knowledge_base / faq）并定义字段结构（Mapping）；② 把工单、知识、FAQ 数据向量化后写进 ES；③ 内置一批示例数据用于演示。

**为什么排这里**：它依赖第 7 步的 `DashScopeEmbedding`。它本身是"一次性运行的脚本"（`if __name__ == "__main__"`），是知识库的初始化入口。

**设计要点**：
- 文件头有一段 `sys.path.insert(0, str(ROOT_DIR))` + `load_dotenv`——因为它是"作为脚本直接运行"的（`python data/ingestion/ingest_docs.py`），Python 默认不会把项目根目录加进搜索路径，所以要手动加，否则 `from data.ingestion...` 会 ImportError。**这是本项目处理"脚本 vs 包"路径问题的标准做法**，第 12 步向量检索器也有同样的 `sys.path.insert`。

## 第 9 步：`data/ingestion/kafka_queue.py` —— Kafka 队列 + 工单路由

**角色**：Kafka 是消息队列，作用是**削峰 + 异步**：工单进来先丢进队列（不阻塞），后端慢慢消费处理。这个文件定义了三个类：生产者（发工单）、消费者（收工单）、路由器（决定工单走规则还是走 LLM）。

**为什么排这里**：路由器 `TicketRouter` 依赖第 4 步的 `RuleEngine`。这一层是"工单接入层"，把前面的清洗/规则能力串起来。

**设计要点**：
- **序列化**：生产者用 `value_serializer=json.dumps(...).encode("utf-8")` 把 dict 转成 JSON 字节流；消费者用对称的 `value_deserializer` 把字节流转回 dict。Kafka 只认字节，序列化/反序列化必须成对。
- `send_ticket()`：自动生成工单号（`GD + 时间戳 + 4位随机`）、提交时间，然后 `send` + `future.get(timeout=10)` 同步等待确认。`acks="all"` 表示所有副本都确认才算成功。
- `consume()`：接收一个 `handler` 回调函数，每消费一条就调一次——**"处理逻辑"和"消费循环"解耦**，调用方只要传个函数进来。
- **`TicketRouter` 是本文件的重头戏**，体现了系统的核心分流逻辑：
  1. 先跑规则引擎 `match`；
  2. 规则命中**且置信度 ≥ 0.8**（呼应第 4 步）→ 直接路由，`route_source="rule"`；
  3. 否则 → 交给 LLM 处理器（`llm_processor`），`route_source="llm"`，并把规则结果作为 `rule_hint` 给 LLM 参考；
  4. 没有 LLM 处理器 → 标记 `rule_low`（规则低置信度，先放着）。
- 三个类的 `__init__` 都有 try/except：连不上 Kafka 就把 `producer`/`consumer` 置 None，方法里再判空——**优雅降级**。

```python
"""
Kafka 工单消息队列
负责：工单缓冲削峰、异步处理、规则路由分发
"""
import os
import json
import logging
import uuid
from datetime import datetime
from typing import Optional, Callable

from kafka import KafkaProducer, KafkaConsumer
from kafka.errors import KafkaError

logger = logging.getLogger(__name__)

KAFKA_BOOTSTRAP = os.getenv("KAFKA_BOOTSTRAP", "localhost:9092")
TOPIC_RAW = os.getenv("KAFKA_TOPIC_RAW", "ticket-raw")
TOPIC_ROUTED = os.getenv("KAFKA_TOPIC_ROUTED", "ticket-routed")


class TicketProducer:
    """工单生产者：将工单发送到 Kafka"""

    def __init__(self):
        try:
            self.producer = KafkaProducer(
                bootstrap_servers=KAFKA_BOOTSTRAP,
                value_serializer=lambda v: json.dumps(v, ensure_ascii=False).encode("utf-8"),
                acks="all",
                retries=3,
            )
            logger.info(f"Kafka Producer 初始化成功，连接: {KAFKA_BOOTSTRAP}")
        except KafkaError as e:
            logger.error(f"Kafka Producer 初始化失败: {e}")
            self.producer = None

    def send_ticket(self, ticket_data: dict) -> bool:
        """发送工单到 ticket-raw topic"""
        if not self.producer:
            logger.error("Producer 未初始化，无法发送")
            return False

        # 添加工单元信息
        ticket_data.setdefault("ticket_id", f"GD{datetime.now().strftime('%Y%m%d%H%M%S')}{uuid.uuid4().hex[:4].upper()}")
        ticket_data.setdefault("submit_time", datetime.now().isoformat())

        try:
            future = self.producer.send(TOPIC_RAW, value=ticket_data)
            future.get(timeout=10)  # 等待发送确认
            logger.info(f"工单 {ticket_data['ticket_id']} 已发送到 {TOPIC_RAW}")
            return True
        except KafkaError as e:
            logger.error(f"工单发送失败: {e}")
            return False

    def close(self):
        if self.producer:
            self.producer.flush()
            self.producer.close()


class TicketConsumer:
    """工单消费者：从 Kafka 拉取工单并处理"""

    def __init__(self, group_id: str = "ticket-agent"):
        self.group_id = group_id
        self.consumer = None
        self._init_consumer()

    def _init_consumer(self):
        """初始化消费者"""
        try:
            self.consumer = KafkaConsumer(
                TOPIC_RAW,
                bootstrap_servers=KAFKA_BOOTSTRAP,
                group_id=self.group_id,
                auto_offset_reset="earliest",
                enable_auto_commit=True,
                value_deserializer=lambda m: json.loads(m.decode("utf-8")),
                consumer_timeout_ms=1000,  # 无消息时 1s 超时退出
            )
            logger.info(f"Kafka Consumer 初始化成功，group: {self.group_id}")
        except KafkaError as e:
            logger.error(f"Kafka Consumer 初始化失败: {e}")

    def consume(self, handler: Callable[[dict], None], max_messages: int = None):
        """
        消费工单消息
        handler: 处理函数，接收工单 dict
        max_messages: 最大消费数量（None 表示持续消费）
        """
        if not self.consumer:
            logger.error("Consumer 未初始化")
            return

        count = 0
        for message in self.consumer:
            try:
                ticket = message.value
                logger.info(f"消费工单: {ticket.get('ticket_id', 'unknown')}")
                handler(ticket)
                count += 1
                if max_messages and count >= max_messages:
                    break
            except Exception as e:
                logger.error(f"处理工单异常: {e}")
                continue

    def close(self):
        if self.consumer:
            self.consumer.close()


class TicketRouter:
    """
    工单路由器：结合规则引擎和 LLM 进行工单分流
    流程：Kafka消费 → 规则匹配 → 命中则直连路由 → 未命中走 LLM 清洗
    """

    def __init__(self, rule_engine, llm_processor=None):
        """
        rule_engine: RuleEngine 实例
        llm_processor: LLM 处理函数（规则未命中时调用）
        """
        self.rule_engine = rule_engine
        self.llm_processor = llm_processor

    def route(self, ticket: dict) -> dict:
        """
        路由工单
        返回: {**ticket, "route_result": {...}}
        """
        raw_text = ticket.get("raw_text", "") or ticket.get("description", "")

        # Step 1: 规则匹配
        rule_result = self.rule_engine.match(raw_text)

        if rule_result["matched"] and rule_result["confidence"] >= 0.8:
            # 规则高置信度命中，直接路由
            ticket["route_source"] = "rule"
            ticket["route_result"] = rule_result
            logger.info(f"工单规则直连路由: {rule_result['category']} (置信度: {rule_result['confidence']:.2f})")
            return ticket

        # Step 2: 规则未命中或低置信度，走 LLM
        if self.llm_processor:
            ticket["route_source"] = "llm"
            ticket["rule_hint"] = rule_result  # 给 LLM 提供参考
            ticket = self.llm_processor(ticket)
            logger.info(f"工单 LLM 路由: {ticket.get('category', 'unknown')}")
        else:
            ticket["route_source"] = "rule_low"
            ticket["route_result"] = rule_result

        return ticket

    def handle_ticket(self, ticket: dict):
        """Kafka 消费者回调：路由工单"""
        routed = self.route(ticket)
        # 这里可以将路由结果写回 ES 或发送到下一个 topic
        logger.info(f"工单路由完成: {routed.get('ticket_id')} → {routed.get('category', 'unknown')}")
        return routed
```

**读完你应掌握**：
- Kafka 生产者/消费者的基本用法（序列化、acks、group_id、回调消费）。
- `TicketRouter.route` 的"规则 → LLM"两级分流，以及 0.8 这个阈值从哪来。
- "处理函数作为参数传入"（`consume(handler=...)`）的解耦写法。

## 第 10 步：`retrieval/query_rewriter.py` —— 查询改写器（检索管道第一环）

**角色**：用户提问是口语化的（"登不上"、"服务器老是 502"），直接拿去搜知识库效果差。这个模块用"同义词表 + LLM"把口语化问题改写成更适合检索的表达，并生成 2~3 个检索变体扩大召回。

**为什么排这里**：它是"检索层"的起点，只依赖 LLM，不依赖其他检索组件；而第 15 步的混合检索管道会把它当第一环。

**设计要点**：
- `REWRITE_PROMPT` 要求 LLM 输出 `rewritten`（主查询）+ `variants`（变体）+ `keywords`（关键词）的 JSON。
- **同义词表 `self.synonyms`** 是"确定性规则"的体现：先在本地把"登不上"扩展成"登录失败 无法登录"，再交给 LLM 精修。**规则先行，LLM 增强**。
- `rewrite()`：先 `_expand_synonyms` 本地扩展，再调 LLM；LLM 失败时返回降级结果（直接用原查询 + 本地扩展的变体）。
- `_extract_keywords()`：用正则直接抽中文词组（2~6 字）和英文单词——这是"无分词库时的土办法关键词提取"。

```python
"""
Query 改写与语义增强模块
通过 LLM 将口语化描述改写为更适合知识库检索的表达
"""
import os
import json
import logging

from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage

logger = logging.getLogger(__name__)

REWRITE_PROMPT = """你是检索查询改写专家。请将下面的工单描述改写为更适合知识库检索的表达。

要求：
1. 去除口语化冗余，保留核心信息
2. 补充领域同义词（如"登不上"→"登录失败"）
3. 保留关键报错码、设备型号等信息
4. 生成 2-3 个检索变体，覆盖不同表述方式

原描述：{query}

请以 JSON 格式输出：
{{
    "rewritten": "改写后的主查询",
    "variants": ["变体1", "变体2"],
    "keywords": ["关键词1", "关键词2"]
}}
"""


class QueryRewriter:
    """Query 改写器"""

    def __init__(self):
        self.llm = ChatOpenAI(
            model=os.getenv("LLM_MODEL", "deepseek-chat"),
            base_url=os.getenv("LLM_BASE_URL", "https://api.deepseek.com"),
            api_key=os.getenv("DEEPSEEK_API_KEY"),
            temperature=0.3,
            max_tokens=1024,
        )

        # 领域同义词表（IT运维/客服场景）
        self.synonyms = {
            "登不上": ["登录失败", "无法登录", "认证失败"],
            "连不上网": ["网络异常", "无法连接", "网络断开"],
            "死机": ["无响应", "卡死", "冻结"],
            "蓝屏": ["BSOD", "系统崩溃"],
            "退款": ["退费", "返还金额"],
            "卡顿": ["响应慢", "延迟高", "运行缓慢"],
        }

    def rewrite(self, query: str) -> dict:
        """
        改写查询
        返回: {"rewritten": str, "variants": list, "keywords": list, "original": str}
        """
        # Step 1: 同义词扩展
        expanded = self._expand_synonyms(query)

        # Step 2: LLM 改写
        try:
            prompt = REWRITE_PROMPT.format(query=query)
            response = self.llm.invoke([HumanMessage(content=prompt)])
            result = self._parse_json(response.content)
            result["original"] = query
            result["expanded"] = expanded
            return result
        except Exception as e:
            logger.error(f"Query 改写失败: {e}")
            return {
                "original": query,
                "rewritten": query,
                "variants": [expanded],
                "keywords": self._extract_keywords(query),
                "expanded": expanded,
            }

    def _expand_synonyms(self, text: str) -> str:
        """基于同义词表扩展"""
        result = text
        for original, synonyms in self.synonyms.items():
            if original in text:
                # 将同义词追加到文本末尾
                result += " " + " ".join(synonyms[:2])
                break
        return result

    def _extract_keywords(self, text: str) -> list:
        """简单关键词提取（基于分词）"""
        import re
        # 提取中文词组（2-6字）和英文单词
        cn_words = re.findall(r'[\u4e00-\u9fa5]{2,6}', text)
        en_words = re.findall(r'[A-Za-z]+[-]?[A-Za-z0-9]*', text)
        # 去重
        keywords = list(set(cn_words + en_words))
        return keywords[:10]

    def _parse_json(self, text: str) -> dict:
        """从 LLM 输出中解析 JSON"""
        import re
        json_match = re.search(r'```(?:json)?\s*(\{.*?\})\s*```', text, re.DOTALL)
        if json_match:
            text = json_match.group(1)
        else:
            json_match = re.search(r'\{.*\}', text, re.DOTALL)
            if json_match:
                text = json_match.group(0)
        try:
            return json.loads(text)
        except json.JSONDecodeError:
            return {"rewritten": text, "variants": [], "keywords": []}
```

**读完你应掌握**：
- "同义词扩展 + LLM 改写"双层策略。
- 检索变体（variants）的意义：多路查询比单一查询召回更多相关文档（第 15 步会用到 `variants`）。

## 第 11 步：`retrieval/hybrid_retriever/bm25_retriever.py` —— BM25 关键词检索器

**角色**：**BM25** 是经典的全文检索排序算法，ES 内置。它靠"词频 + 文档频率"给文档打分——简单说：查询词在文档里出现得越频繁（且该词越罕见），文档得分越高。这条路擅长**精确关键词匹配**（比如搜"502"、"密码重置"）。

**为什么排这里**：它是混合检索的"召回器"之一，只依赖 ES，无项目内依赖；第 15 步会用到它。

**设计要点**：
- 用 ES 的 `multi_match` 查询，同时搜多个字段（description/content/title/question/resolution/solution），`type: best_fields` 取匹配最好的那个字段的分数，`analyzer: ik_smart` 检索时用精分。
- `search()` 支持传多个索引，逐个索引搜完合并，按分数排序取前 N。
- `_extract_content()`：从返回的文档里挑第一个非空的文本字段作为"内容"——因为不同索引的字段名不一样（工单是 description，知识是 content，FAQ 是 question），这个函数统一抽取。
- 每个索引的搜索都被 try/except 包住，某个索引挂了不影响其他索引——又是兜底。

```python
"""
BM25 全文检索器
基于 Elasticsearch IK 分词的关键词精确匹配检索
"""
import os
import logging
from elasticsearch import Elasticsearch

logger = logging.getLogger(__name__)

ES_HOST = os.getenv("ES_HOST", "http://localhost:9200")


class BM25Retriever:
    """ES BM25 全文检索器"""

    def __init__(self, index: str = "knowledge_base"):
        self.es = Elasticsearch(ES_HOST)
        self.index = index

    def search(self, query: str, size: int = 20, indices: list = None) -> list:
        """
        BM25 检索
        返回: [{"id": str, "score": float, "content": str, "source": dict}, ...]
        """
        search_indices = indices or [self.index]
        results = []

        for idx in search_indices:
            try:
                body = {
                    "query": {
                        "multi_match": {
                            "query": query,
                            "fields": ["description", "content", "title", "question", "resolution", "solution"],
                            "type": "best_fields",
                            "analyzer": "ik_smart",
                        }
                    },
                    "size": size,
                }
                resp = self.es.search(index=idx, body=body)

                for hit in resp["hits"]["hits"]:
                    results.append({
                        "id": hit["_id"],
                        "score": hit["_score"],
                        "content": self._extract_content(hit["_source"]),
                        "source": hit["_source"],
                        "index": idx,
                    })
            except Exception as e:
                logger.error(f"BM25 检索索引 {idx} 失败: {e}")

        # 按分数排序
        results.sort(key=lambda x: x["score"], reverse=True)
        return results[:size]

    def _extract_content(self, source: dict) -> str:
        """从文档中提取主要文本内容"""
        for field in ["content", "description", "question", "title"]:
            if field in source and source[field]:
                return source[field]
        return ""
```

**读完你应掌握**：
- BM25 是什么（关键词匹配 + 相关性打分），靠 IK 分词支持中文。
- ES `multi_match` 多字段检索的写法。
- 返回结构 `{"id", "score", "content", "source", "index"}` 是检索层统一的"文档格式"，后面融合、重排都按这个结构处理。

## 第 12 步：`retrieval/hybrid_retriever/vector_retriever.py` —— 向量语义检索器

**角色**：BM25 只能匹配"字面相同"的词，遇到"手环待机短"和"手环续航差"这种**字面不同但语义相同**的说法就抓瞎。向量检索解决这个问题：先把查询向量化，再用 ES 的 **knn（k 近邻）** 找向量空间里最相近的文档。这条路擅长**语义相似**。

**为什么排这里**：它依赖第 7 步的 `DashScopeEmbedding`（生成查询向量），所以必须在第 7 步之后读。

**设计要点**：
- 结构几乎和 BM25 检索器一模一样（同样的 `search`、`_extract_content`），区别只在查询体：用 `"knn"` 而不是 `"query"`。
- `"knn"` 里的关键参数：`field`（向量字段名 `content_vector`）、`query_vector`（查询向量）、`k`（返回几个）、`num_candidates`（候选数，通常是 k 的 4 倍，用"先粗筛再精排"提升速度）。
- 文件头同样有 `sys.path.insert` 解决脚本/包导入问题。

```python

向量语义检索器
```

## 第 13 步：`retrieval/hybrid_retriever/fusion.py` —— RRF 融合排序

**角色**：BM25 和向量检索各返回一份排序结果，两份结果怎么合并成一份？**RRF（Reciprocal Rank Fusion，倒数排名融合）** 是业界标准答案：不看每路给的具体分数（因为两路的分数不可比），只看"排名"，用公式 `score = Σ 1/(k + rank)` 把多路的排名融合成一个综合分。

**为什么排这里**：它是纯函数，无外部依赖，被第 15 步调用。

**设计要点**：
- `rrf_fusion(result_lists, k=60)`：`k=60` 是经验常数（业界常用 60），用来"软化"排名差异。
- 逻辑：遍历每一路结果，每个文档按其在各自列表里的排名累加 `1/(60+rank)`；同一文档在多路都出现就累加（所以"两路都排前面"的文档会得高分）。
- `doc_map` 用来记录每个文档的详情，并**保留原始分数最高的那份**——因为融合后还要展示内容。
- 用 `defaultdict(float)` 免去"key 不存在要先初始化"的样板代码。

```python
"""
RRF (Reciprocal Rank Fusion) 融合排序
将 BM25 和向量检索的结果融合为统一排序
"""
import logging
from collections import defaultdict

logger = logging.getLogger(__name__)


def rrf_fusion(result_lists: list[list], k: int = 60) -> list:
    """
    RRF 融合排序算法
    score(d) = Σ 1 / (k + rank_i(d))

    参数:
        result_lists: 多路检索结果列表，每路为 [{"id": ..., "score": ..., ...}, ...]
        k: RRF 常数（默认 60）
    返回:
        融合排序后的结果列表
    """
    # 计算每个文档的 RRF 分数
    rrf_scores = defaultdict(float)
    doc_map = {}  # id → 文档详情

    for results in result_lists:
        for rank, doc in enumerate(results, start=1):
            doc_id = doc["id"]
            rrf_scores[doc_id] += 1.0 / (k + rank)
            # 保留最高原始分数的文档详情
            if doc_id not in doc_map or doc["score"] > doc_map[doc_id]["score"]:
                doc_map[doc_id] = doc

    # 按 RRF 分数排序
    sorted_ids = sorted(rrf_scores.keys(), key=lambda x: rrf_scores[x], reverse=True)

    fused = []
    for doc_id in sorted_ids:
        doc = doc_map[doc_id].copy()
        doc["rrf_score"] = rrf_scores[doc_id]
        fused.append(doc)

    logger.info(f"RRF 融合: {len(result_lists)} 路 → {len(fused)} 条结果")
    return fused
```

**读完你应掌握**：
- RRF 的核心思想：**融合只看排名、不看绝对分数**（解决异构分数不可比问题）。
- 同一个文档在两路都靠前 → RRF 分更高 → 排更前。这就是"混合检索"能同时吸收字面匹配和语义匹配优点的机制。

## 第 14 步：`retrieval/reranker/reranker.py` —— 重排序（精排）

**角色**：RRF 融合后可能有几十条候选，但用户只想看最相关的 10 条。**Rerank（重排序）** 用一个专门的模型（阿里云 `gte-rerank-v2`）把"查询"和"每一条候选文档"两两配对，重新算一个更精确的相关性分，再按新分排序。粗排（召回）图快，精排（Rerank）图准，两级分工。

**为什么排这里**：它是检索管道的最后一关，被第 15 步调用。

**设计要点**：
- `TextReRank.call(query=..., documents=[...], top_n=...)`：把查询和候选文档列表一起丢给模型。
- `return_documents=False`：只要排序结果（index + 分数），不要模型回传文档原文，省流量。
- 响应里 `item.index` 指向原 `documents` 列表的下标，据此把原始文档找回来，并附上 `rerank_score`。
- 失败兜底：直接返回原列表前 N 条（`documents[:top_n]`）——**降级为"不精排"**，保证流程不断。

```python
"""
重排序模块
使用阿里云 DashScope gte-rerank-v2 进行精排（替代 BGE-Reranker / BGE-M3）
"""
import os
import logging

import dashscope
from dashscope import TextReRank

logger = logging.getLogger(__name__)


class DashScopeReranker:
    """阿里云 DashScope Rerank 服务"""

    def __init__(self, model: str = None):
        self.model = model or os.getenv("RERANK_MODEL", "gte-rerank-v2")
        self.api_key = os.getenv("DASHSCOPE_API_KEY", "")
        self.top_n = 10
        dashscope.api_key = self.api_key

    def rerank(self, query: str, documents: list[dict], top_n: int = None) -> list:
        """
        重排序
        参数:
            query: 查询文本
            documents: 候选文档列表 [{"id": str, "content": str, ...}, ...]
            top_n: 返回前 N 条
        返回:
            重排序后的文档列表
        """
        if not documents:
            return []

        top_n = top_n or self.top_n
        contents = [doc.get("content", "") for doc in documents]

        try:
            resp = TextReRank.call(
                model=self.model,
                query=query,
                documents=contents,
                top_n=top_n,
                return_documents=False,
            )

            if resp.status_code == 200:
                reranked = []
                for item in resp.output.results:
                    doc = documents[item.index].copy()
                    doc["rerank_score"] = item.relevance_score
                    reranked.append(doc)
                logger.info(f"Rerank 完成: {len(documents)} → {len(reranked)} 条")
                return reranked
            else:
                logger.error(f"Rerank 调用失败: {resp.code} - {resp.message}")
                return documents[:top_n]

        except Exception as e:
            logger.error(f"Rerank 异常: {e}")
            return documents[:top_n]
```

**读完你应掌握**：
- 召回（BM25/向量）与精排（Rerank）的分工：先多找、再精选。
- Rerank 的输入是"查询 + 候选列表"，输出是"重排后的列表"，`item.index` 是回填原文的桥梁。

## 第 15 步：`retrieval/hybrid_search.py` —— 混合检索总管道（组装第 10~14 步）

**角色**：把前面 5 步（改写、BM25、向量、融合、重排）串成一条完整的检索流水线：**Query 改写 → BM25 + 向量并行召回 → RRF 融合 → Rerank 精排**。这是整个"知识检索"能力的最终出口。

**为什么排这里**：它 `import` 了第 10~14 步的全部模块，是检索层的"总装车间"，必须在所有零件之后读。

**设计要点**：
- `__init__` 里一次性实例化 4 个组件（rewriter/bm25/vector/reranker），默认检索三个索引 `["knowledge_base", "tickets", "faq"]`。
- `search()` 是主流程，逐步对照注释看：
  1. 改写查询，拿到 `main_query` + `variants`；
  2. **多查询并行召回**：用主查询 + 前 2 个变体，分别跑 BM25 和向量检索，结果累加（`extend`）——这就是"多路召回"，变体越多召回越全；
  3. `_deduplicate` 按文档 id 去重（同一文档可能被多个查询、多路检索重复命中）；
  4. `rrf_fusion` 融合（第 13 步）；
  5. `reranker.rerank` 精排（第 14 步），返回 top_k 条。
- `_deduplicate()`：用 `set` 记录见过的 id，保序去重——`set` 判重 O(1)，是去重标准做法。

```python
"""
混合检索管道
整合：Query改写 → BM25 + 向量检索 → RRF融合 → Rerank精排
"""
import os
import sys
import logging

sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
from retrieval.query_rewriter import QueryRewriter
from retrieval.hybrid_retriever.bm25_retriever import BM25Retriever
from retrieval.hybrid_retriever.vector_retriever import VectorRetriever
from retrieval.hybrid_retriever.fusion import rrf_fusion
from retrieval.reranker.reranker import DashScopeReranker

logger = logging.getLogger(__name__)


class HybridSearchPipeline:
    """
    混合检索管道
    Query改写 → BM25 + 向量并行召回 → RRF融合 → Rerank精排
    """

    def __init__(self, indices: list = None):
        """
        indices: 要检索的 ES 索引列表，默认 ["knowledge_base", "tickets", "faq"]
        """
        self.indices = indices or ["knowledge_base", "tickets", "faq"]
        self.rewriter = QueryRewriter()
        self.bm25 = BM25Retriever()
        self.vector = VectorRetriever()
        self.reranker = DashScopeReranker()

    def search(self, query: str, top_k: int = 10) -> list:
        """
        完整混合检索流程
        返回: top_k 条精排后的结果
        """
        # Step 1: Query 改写
        rewrite_result = self.rewriter.rewrite(query)
        main_query = rewrite_result.get("rewritten", query)
        variants = rewrite_result.get("variants", [])

        logger.info(f"Query改写: '{query}' → '{main_query}'")

        # Step 2: 多路并行检索
        all_queries = [main_query] + variants[:2]
        bm25_results = []
        vector_results = []

        for q in all_queries:
            bm25_results.extend(self.bm25.search(q, size=10, indices=self.indices))
            vector_results.extend(self.vector.search(q, size=10, indices=self.indices))

        # 去重（按 id）
        bm25_results = self._deduplicate(bm25_results)
        vector_results = self._deduplicate(vector_results)

        logger.info(f"检索召回: BM25={len(bm25_results)}, Vector={len(vector_results)}")

        # Step 3: RRF 融合
        fused = rrf_fusion([bm25_results, vector_results], k=60)
        logger.info(f"RRF融合后: {len(fused)} 条")

        # Step 4: Rerank 精排
        reranked = self.reranker.rerank(main_query, fused, top_n=top_k)
        logger.info(f"Rerank精排后: {len(reranked)} 条")

        return reranked

    def _deduplicate(self, results: list) -> list:
        """按文档 ID 去重"""
        seen = set()
        unique = []
        for doc in results:
            if doc["id"] not in seen:
                seen.add(doc["id"])
                unique.append(doc)
        return unique
```

**读完你应掌握**：
- 一条查询从进来到出去，中间经历了"改写 → 多路召回 → 去重 → 融合 → 精排"完整链路。
- "多查询 + 多检索器"的组合拳如何扩大召回；去重、融合、精排各自解决什么问题。
- 这个 `HybridSearchPipeline.search()` 就是第 16 步 `search_knowledge` 工具、第 27 步知识检索页背后的引擎。

## 第 16 步：`tools/function_tools.py` —— FunctionCall 工具定义与执行

**角色**：大模型只会"说话"，不会"干活"。**Function Calling（函数调用）** 让模型在需要时输出一个"我要调用某个工具、参数是什么"的结构化请求，程序收到后真正执行，再把结果喂回给模型。这个文件就是"工具箱"：上半部分 `TOOLS_DEFINITION` 定义有哪些工具（给模型看的说明书），下半部分 `TicketTools` 真正实现这些工具（干活的代码）。

**为什么排这里**：它是 Agent 的"手"。第 20 步的工单 Agent、第 23 步的编排都要用它。它自己依赖 ES 和检索管道（可选注入）。

**设计要点**：
- `TOOLS_DEFINITION` 是 OpenAI Function Calling 的 JSON Schema 格式：每个工具声明 `name`（工具名）、`description`（什么时候用，模型靠它判断该不该调用）、`parameters`（参数 schema，含 `required` 必填项和 `enum` 枚举）。**description 写得好坏直接决定模型会不会正确调用工具**。
- 四个工具：`create_ticket`（创建工单）、`query_ticket_status`（查状态）、`search_knowledge`（查知识）、`assign_engineer`（派单）。
- `TicketTools.execute_tool()`：用 `tool_map` 字典把工具名映射到方法，实现"按名字分发"——这是简单的命令模式。
- **内存 + ES 双存储**：`self._tickets = {}` 是内存字典（进程内缓存），有 ES 时同步写 ES。`create_ticket` 先写内存，再尝试写 ES（失败只 warning）。`query_ticket_status` 和 `assign_engineer` 都是"先查内存，没有再查 ES"。这样**没有 ES 也能跑**（退化成纯内存演示模式）。
- 工单号生成规则 `GD + 时间戳(14位) + 4位随机大写`，与第 9 步 Kafka 生产者一致。
- 每个方法都有 try/except + 明确的 `{"success": bool, "message": ...}` 返回结构——调用方靠 `success` 判断成败，靠 `message` 拿人话。

```python
class TicketTools:
    """工单工具执行器"""

    def __init__(self, es_client=None, search_pipeline=None):
        """
        es_client: Elasticsearch 客户端
        search_pipeline: HybridSearchPipeline 实例
        """
        self.es = es_client
        self.search_pipeline = search_pipeline
        # 内存中的工单存储（生产环境应使用 ES 或数据库）
        self._tickets = {}

    def execute_tool(self, tool_name: str, arguments: dict) -> dict:
        """执行工具调用"""
        tool_map = {
            "create_ticket": self.create_ticket,
            "query_ticket_status": self.query_ticket_status,
            "search_knowledge": self.search_knowledge,
            "assign_engineer": self.assign_engineer,
        }

        func = tool_map.get(tool_name)
        if not func:
            return {"error": f"未知工具: {tool_name}"}

        try:
            return func(**arguments)
        except Exception as e:
            logger.error(f"工具 {tool_name} 执行失败: {e}")
            return {"error": str(e)}

    def create_ticket(self, problem_type: str, description: str,
                      product: str = None, urgency: str = "中") -> dict:
        """创建工单"""
        ticket_id = f"GD{datetime.now().strftime('%Y%m%d%H%M%S')}{uuid.uuid4().hex[:4].upper()}"
        ticket = {
            "ticket_id": ticket_id,
            "problem_type": problem_type,
            "description": description,
            "product": product,
            "urgency": urgency,
            "status": "open",
            "created_at": datetime.now().isoformat(),
            "assigned_to": None,
        }
        self._tickets[ticket_id] = ticket

        # 写入 ES（如果可用）
        if self.es:
            try:
                self.es.index(index="tickets", id=ticket_id, document=ticket)
            except Exception as e:
                logger.warning(f"写入 ES 失败: {e}")

        logger.info(f"工单创建成功: {ticket_id}")
        return {
            "success": True,
            "ticket_id": ticket_id,
            "message": f"工单 {ticket_id} 已创建，问题类型: {problem_type}，紧急程度: {urgency}",
        }

    def query_ticket_status(self, ticket_id: str) -> dict:
        """查询工单状态"""
        # 先从内存查
        ticket = self._tickets.get(ticket_id)

        # 内存没有则查 ES
        if not ticket and self.es:
            try:
                resp = self.es.get(index="tickets", id=ticket_id)
                ticket = resp["_source"]
            except Exception:
                pass

        if not ticket:
            return {"success": False, "message": f"未找到工单 {ticket_id}"}

        return {
            "success": True,
            "ticket": {
                "ticket_id": ticket.get("ticket_id"),
                "status": ticket.get("status"),
                "problem_type": ticket.get("problem_type"),
                "description": ticket.get("description"),
                "urgency": ticket.get("urgency"),
                "assigned_to": ticket.get("assigned_to"),
                "created_at": ticket.get("created_at"),
            },
        }

    def search_knowledge(self, query: str, category: str = None) -> dict:
        """检索知识库"""
        if self.search_pipeline:
            results = self.search_pipeline.search(query, top_k=5)
            return {
                "success": True,
                "query": query,
                "results": [
                    {
                        "title": r.get("source", {}).get("title", ""),
                        "content": r.get("content", ""),
                        "score": r.get("rerank_score", r.get("score", 0)),
                        "category": r.get("source", {}).get("category", ""),
                    }
                    for r in results
                ],
            }
        else:
            return {"success": False, "message": "检索服务未初始化"}

    def assign_engineer(self, ticket_id: str, skill_group: str, reason: str = None) -> dict:
        """派单给工程师"""
        ticket = self._tickets.get(ticket_id)
        if not ticket and self.es:
            try:
                resp = self.es.get(index="tickets", id=ticket_id)
                ticket = resp["_source"]
            except Exception:
                pass

        if not ticket:
            return {"success": False, "message": f"未找到工单 {ticket_id}"}

        # 更新工单
        ticket["assigned_to"] = skill_group
        ticket["status"] = "assigned"
        ticket["assign_reason"] = reason
        self._tickets[ticket_id] = ticket

        if self.es:
            try:
                self.es.index(index="tickets", id=ticket_id, document=ticket)
            except Exception as e:
                logger.warning(f"更新 ES 失败: {e}")

        return {
            "success": True,
            "message": f"工单 {ticket_id} 已派发给 {skill_group}" + (f"，原因: {reason}" if reason else ""),
        }
```

## 第 17 步：`tools/mcp_ticket_server.py` —— MCP 服务封装

**角色**：**MCP（Model Context Protocol）** 是一种"让 AI 应用标准化调用工具/资源"的开放协议。这个文件把第 16 步的工单工具包装成 MCP 服务，让外部 Agent（不限本项目）能通过 MCP 协议调用工单系统的能力。

**为什么排这里**：它依赖第 16 步的 `TOOLS_DEFINITION` 和 `TicketTools`。

**设计要点**：
- `MCPTicketServer` 包一层 `TicketTools`，提供 `get_tool_descriptions`（把工具 schema 暴露出去）和 `handle_tool_call`（转发调用）。
- `get_mcp_config()` 返回一个配置字典，声明这个 MCP server 用 `python tools/mcp_ticket_server.py` 以 **stdio** 方式启动——这是给 `langchain-mcp-adapters` 用的。
- `if __name__ == "__main__"` 部分是**极简的 JSON-RPC 循环**：从 stdin 逐行读 JSON 请求，识别 `tools/list`（列工具）和 `tools/call`（调工具）两个方法，结果打印到 stdout。stdio 模式下，MCP 客户端和服务器就是靠 stdin/stdout 交换 JSON 消息。
- 注意 `handle_tool_call` 是 `async def`——为真正的异步 MCP 框架预留；但 `__main__` 里的循环是同步的，属于"协议的最小演示实现"。

```python
"""
MCP Server 封装
将工单系统 API 封装为 MCP (Model Context Protocol) 服务
供 Agent 通过 MCP 协议统一调用
"""
import json
import logging
from typing import Any

logger = logging.getLogger(__name__)


class MCPTicketServer:
    """
    MCP 工单服务
    将工单操作封装为标准 MCP 工具描述
    支持 stdio / SSE 两种传输方式
    """

    def __init__(self, ticket_tools):
        """
        ticket_tools: TicketTools 实例
        """
        self.ticket_tools = ticket_tools

    def get_tool_descriptions(self) -> list:
        """获取 MCP 工具描述列表"""
        from tools.function_tools import TOOLS_DEFINITION
        return TOOLS_DEFINITION

    async def handle_tool_call(self, tool_name: str, arguments: dict) -> dict:
        """处理 MCP 工具调用"""
        logger.info(f"MCP 工具调用: {tool_name}({json.dumps(arguments, ensure_ascii=False)})")
        result = self.ticket_tools.execute_tool(tool_name, arguments)
        logger.info(f"MCP 工具结果: {json.dumps(result, ensure_ascii=False)[:200]}")
        return result

    def get_mcp_config(self) -> dict:
        """获取 MCP Server 配置（用于 langchain-mcp-adapters）"""
        return {
            "ticket_system": {
                "command": "python",
                "args": ["tools/mcp_ticket_server.py"],
                "transport": "stdio",
            }
        }


# ========== 独立运行 MCP Server（stdio 模式） ==========

if __name__ == "__main__":
    import sys
    sys.path.insert(0, ".")

    from tools.function_tools import TicketTools, TOOLS_DEFINITION

    tools = TicketTools()
    server = MCPTicketServer(tools)

    # stdio 模式：从 stdin 读取 JSON-RPC 请求
    logger.info("MCP Ticket Server 启动（stdio 模式）")

    for line in sys.stdin:
        line = line.strip()
        if not line:
            continue

        try:
            request = json.loads(line)
            method = request.get("method", "")

            if method == "tools/list":
                response = {"result": server.get_tool_descriptions()}
            elif method == "tools/call":
                params = request.get("params", {})
                tool_name = params.get("name")
                arguments = params.get("arguments", {})
                result = server.handle_tool_call(tool_name, arguments)
                response = {"result": result}
            else:
                response = {"error": f"未知方法: {method}"}

            print(json.dumps(response, ensure_ascii=False), flush=True)

        except Exception as e:
            error_resp = {"error": str(e)}
            print(json.dumps(error_resp, ensure_ascii=False), flush=True)
```

## 第 18 步：`agents/intent_agent.py` —— 意图识别 Agent（编排第一环）

**角色**：用户一句话进来，系统第一步要判断他到底想干嘛：是要**创建工单**（报障）、**查工单**（催进度）、**搜知识**（自助解决）、**转人工**（派单）、还是纯**闲聊**。这个 Agent 用 LLM 做五分类。

**为什么排这里**：从这一步起进入"Agent 层"。意图识别是 LangGraph 编排的入口节点（第 23 步），它不依赖其他 Agent，所以最先读。

**设计要点**：
- `SYSTEM_PROMPT`（系统提示词）定义角色和分类标准，`USER_PROMPT`（用户提示词）带 `{user_input}` 占位符——**系统提示词 + 用户提示词**是 LLM 对话的标准结构。
- `recognize()`：拼消息 → 调 LLM → 解析 JSON → **校验意图类别**（如果模型胡诌了一个不在枚举里的意图，就降级成 `chitchat`，置信度 0.5）。
- 异常兜底：LLM 挂了返回 `chitchat` + 低置信度——**保证编排流程永远有个结果能继续往下走**。
- `_parse_json` 又是熟悉的"正则抠 JSON"（第 6 步讲过，全文复用）。

```python
            model=os.getenv("LLM_MODEL", "deepseek-chat"),

        识别用户意图
        返回: {"intent": str, "confidence": float, "reason": str}
        """

                SystemMessage(content=SYSTEM_PROMPT),
                HumanMessage(content=USER_PROMPT.format(user_input=user_input)),

        import re
        json_match = re.search(r'```(?:json)?\s*(\{.*?\})\s*```', text, re.DOTALL)
        if json_match:
            text = json_match.group(1)
        else:

            if json_match:
                text = json_match.group(0)
```

## 第 19 步：`agents/slot_filling_agent.py` —— 槽位填充 Agent（编排第二环）

**角色**：意图是"创建工单"后，系统要收集**创建工单所需的参数**（问题类型、描述、产品、紧急程度、设备、错误码）——这些参数叫**槽位（slot）**。这个 Agent 从用户输入里抽槽位，缺了必填槽位就生成追问。

**为什么排这里**：它是意图识别之后的第二个节点，独立无依赖。

**设计要点**：
- `REQUIRED_SLOTS = ["problem_type", "description"]`：只有这两个是必填，其余可选（呼应第 2 步 agent_config.yaml 里的配置）。
- `SLOT_EXTRACTION_PROMPT` 要求每个槽位输出 `{value, confidence}` 结构，以及缺失必填槽位列表和追问消息。
- `fill()` 核心逻辑：只接受**置信度 ≥ 0.7** 的槽位（`CONFIDENCE_THRESHOLD`），存入 `self.slots`；然后检查两个必填槽位是否都填上了。
- **有状态**：`self.slots` 是实例属性，`fill()` 只更新不重置——意味着多轮对话中，之前填的槽位会**累积**（用户第一句说了"设备"，第二句补充"描述"，两次的槽位会合并）。`reset()` 手动清空。
- 异常兜底返回"请描述您遇到的问题…"。

```python
"""
槽位填充 Agent
从用户输入中提取工单关键参数，缺失时自动追问
"""
import os
import json
import logging

from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage, SystemMessage

logger = logging.getLogger(__name__)

SLOT_EXTRACTION_PROMPT = """你是工单槽位填充专家。请从用户输入中提取以下槽位信息。

槽位定义：
- problem_type: 问题类型（登录问题/系统故障/网络异常/设备故障/财务问题）
- description: 问题描述（规范化表达）
- product: 产品/系统名称
- urgency: 紧急程度（高/中/低）
- device: 设备名称/型号
- error_code: 错误码

用户输入：{user_input}

已有上下文信息：{context}

请以 JSON 格式输出：
{{
    "slots": {{
        "problem_type": {{"value": "...", "confidence": 0.0-1.0}},
        "description": {{"value": "...", "confidence": 0.0-1.0}},
        "product": {{"value": "...", "confidence": 0.0-1.0}},
        "urgency": {{"value": "...", "confidence": 0.0-1.0}},
        "device": {{"value": "...", "confidence": 0.0-1.0}},
        "error_code": {{"value": "...", "confidence": 0.0-1.0}}
    }},
    "missing_required": ["缺失的必填槽位列表"],
    "follow_up": "追问消息（如有缺失必填槽位）"
}}
"""


class SlotFillingAgent:
    """槽位填充 Agent"""

    REQUIRED_SLOTS = ["problem_type", "description"]
    CONFIDENCE_THRESHOLD = 0.7

    def __init__(self):
        self.llm = ChatOpenAI(
            model=os.getenv("LLM_MODEL", "deepseek-chat"),
            base_url=os.getenv("LLM_BASE_URL", "https://api.deepseek.com"),
            api_key=os.getenv("DEEPSEEK_API_KEY"),
            temperature=0.1,
            max_tokens=1024,
        )
        self.slots = {}  # 已填充的槽位

    def fill(self, user_input: str, context: dict = None) -> dict:
        """
        从用户输入中填充槽位
        返回: {"slots": dict, "complete": bool, "follow_up": str or None}
        """
        context_str = json.dumps(context or {}, ensure_ascii=False)

        try:
            prompt = SLOT_EXTRACTION_PROMPT.format(
                user_input=user_input,
                context=context_str,
            )
            response = self.llm.invoke([HumanMessage(content=prompt)])
            result = self._parse_json(response.content)

            # 更新槽位
            extracted_slots = result.get("slots", {})
            for slot_name, slot_info in extracted_slots.items():
                if slot_info.get("value") and slot_info.get("confidence", 0) >= self.CONFIDENCE_THRESHOLD:
                    self.slots[slot_name] = slot_info["value"]

            # 检查完整性
            complete = all(
                slot in self.slots
                for slot in self.REQUIRED_SLOTS
            )

            follow_up = result.get("follow_up") if not complete else None

            return {
                "slots": self.slots.copy(),
                "complete": complete,
                "follow_up": follow_up,
            }

        except Exception as e:
            logger.error(f"槽位填充失败: {e}")
            return {
                "slots": self.slots.copy(),
                "complete": False,
                "follow_up": "请描述您遇到的问题，包括问题类型和具体情况。",
            }

    def reset(self):
        """重置槽位"""
        self.slots = {}

    def get_filled_slots(self) -> dict:
        """获取已填充的槽位"""
        return self.slots.copy()

    def _parse_json(self, text: str) -> dict:
        """解析 JSON"""
        import re
        json_match = re.search(r'```(?:json)?\s*(\{.*?\})\s*```', text, re.DOTALL)
        if json_match:
            text = json_match.group(1)
        else:
            json_match = re.search(r'\{.*\}', text, re.DOTALL)
            if json_match:
                text = json_match.group(0)
        try:
            return json.loads(text)
        except json.JSONDecodeError:
            return {"slots": {}, "missing_required": self.REQUIRED_SLOTS, "follow_up": "请提供更多信息。"}
```

- 槽位填充的"抽取 → 置信度过滤 → 完整性检查 → 追问"四步。
- 有状态 Agent 的"累积式填充"设计（多轮对话的雏形）。
- 必填/可选槽位与配置文件的对应关系。

## 第 20 步：`agents/ticket_agent.py` —— 工单创建/查询 Agent（会用工具的 Agent）

**角色**：这是第一个"会用工具"的 Agent。它把第 16 步的工具绑定到 LLM 上，让模型**自主决定**该调用哪个工具、传什么参数，然后把工具执行结果喂回模型生成最终回复。

**为什么排这里**：它依赖第 16 步的 `TOOLS_DEFINITION` 和 `TicketTools`。

**设计要点**：
- `__init__(self, ticket_tools)`：**注入** `TicketTools` 实例，并 `from tools.function_tools import TOOLS_DEFINITION` 拿工具 schema。
- `process()` 是 Function Calling 的完整循环，仔细看：
  1. 拼 system + context + human 消息；
  2. `self.llm.bind_tools(self.tools_def).invoke(messages)` —— **`bind_tools` 是关键**：把工具定义挂到模型上，模型就会在需要时返回 `tool_calls`（而不是纯文本）；
  3. 若 `response.tool_calls` 非空：逐个执行 `self.ticket_tools.execute_tool(...)`，把结果作为新的 `HumanMessage` 追加回对话，**再调一次 LLM** 让它看着工具结果生成自然语言回复（这是"两段式"：先决策调工具，再基于结果生成话术）；
  4. 从工具结果里提取 `ticket_id`；
  5. 若无工具调用，直接用第一次回复。
- 整个函数套 try/except，出错返回道歉话术。

```python
"""
工单创建/查询 Agent
通过 DeepSeek FunctionCall 自主决策创建或查询工单
"""
import os
import json
import logging

from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage, SystemMessage, AIMessage

logger = logging.getLogger(__name__)

SYSTEM_PROMPT = """你是智能工单系统的工单处理助手。你可以帮助用户：
1. 创建工单 - 当用户报告问题时
2. 查询工单 - 当用户询问工单状态时
3. 搜索知识 - 当用户寻找解决方案时

工作规则：
- 创建工单前，确保收集到问题类型和问题描述（必填）
- 如果信息不完整，友好地追问用户补充
- 调用工具时，严格按照工具参数要求传入参数
- 回复用户时使用中文，语气友好专业
"""


class TicketAgent:
    """工单创建/查询 Agent"""

    def __init__(self, ticket_tools):
        """
        ticket_tools: TicketTools 实例
        """
        self.ticket_tools = ticket_tools
        self.llm = ChatOpenAI(
            model=os.getenv("LLM_MODEL", "deepseek-chat"),
            base_url=os.getenv("LLM_BASE_URL", "https://api.deepseek.com"),
            api_key=os.getenv("DEEPSEEK_API_KEY"),
            temperature=0.3,
            max_tokens=2048,
        )
        # 绑定 FunctionCall 工具
        from tools.function_tools import TOOLS_DEFINITION
        self.tools_def = TOOLS_DEFINITION

    def process(self, user_input: str, context: dict = None) -> dict:
        """
        处理用户输入，自主决策是否调用工具
        返回: {"response": str, "tool_calls": list, "ticket_id": str or None}
        """
        messages = [SystemMessage(content=SYSTEM_PROMPT)]

        # 添加上下文
        if context:
            context_msg = f"当前对话上下文：{json.dumps(context, ensure_ascii=False)}"
            messages.append(SystemMessage(content=context_msg))

        messages.append(HumanMessage(content=user_input))

        try:
            # 调用 LLM（带工具）
            response = self.llm.bind_tools(self.tools_def).invoke(messages)

            # 检查是否有工具调用
            if response.tool_calls:
                tool_results = []
                for tc in response.tool_calls:
                    tool_name = tc["name"]
                    tool_args = tc["args"]
                    logger.info(f"FunctionCall: {tool_name}({tool_args})")

                    # 执行工具
                    result = self.ticket_tools.execute_tool(tool_name, tool_args)
                    tool_results.append({
                        "tool": tool_name,
                        "args": tool_args,
                        "result": result,
                    })

                # 将工具结果反馈给 LLM 生成最终回复
                messages.append(response)
                for tr in tool_results:
                    messages.append(HumanMessage(
                        content=f"工具 {tr['tool']} 执行结果：{json.dumps(tr['result'], ensure_ascii=False)}"
                    ))
                final_response = self.llm.invoke(messages)

                # 提取工单ID
                ticket_id = None
                for tr in tool_results:
                    if tr["result"].get("ticket_id"):
                        ticket_id = tr["result"]["ticket_id"]

                return {
                    "response": final_response.content,
                    "tool_calls": tool_results,
                    "ticket_id": ticket_id,
                }
            else:
                # 无工具调用，直接回复
                return {
                    "response": response.content,
                    "tool_calls": [],
                    "ticket_id": None,
                }

        except Exception as e:
            logger.error(f"TicketAgent 处理失败: {e}")
            return {
                "response": f"抱歉，处理您的请求时出现错误：{e}。请稍后重试。",
                "tool_calls": [],
                "ticket_id": None,
            }
```

**读完你应掌握**：
- LangChain 里 `bind_tools` 的用法，以及"模型返回 tool_calls → 执行 → 结果回喂 → 再生成"的 Function Calling 循环。
- 工具调用是"模型决策、程序执行、结果回喂"三段式协作。

## 第 21 步：`agents/assign_agent.py` —— 智能派单 Agent（规则优先 + LLM 兜底）

**角色**：工单创建后要派给谁？这个 Agent 决定把工单分配给哪个技能组（IT支持组 / 维修工程师 / 财务组 / 客服组）。核心策略还是那句话：**能上规则就不用 LLM**。

**为什么排这里**：它复用了"规则优先、LLM 兜底"的思想，独立无项目内依赖。

**设计要点**：
- `CATEGORY_TO_GROUP` 字典是"问题类型 → 技能组"的**确定性映射**（与第 2 步配置里的 skill_groups 呼应）。类别命中就直接路由，不调 LLM。
- 规则没命中（未知类别）才走 `_llm_assign`：用 `ASSIGN_PROMPT` 让 LLM 输出技能组/优先级/理由/预计时间。
- `assign()` 三步：规则匹配 → 不行就 LLM → 拿到结果后若 `ticket_id` 和 `ticket_tools` 都在，真正执行 `assign_engineer` 工具（把派单结果落库）。
- 双重兜底：LLM 决策失败 → 默认派"客服组"；JSON 解析失败 → 也默认"客服组"。

```python
"""
智能派单 Agent
根据工单类型、优先级和技能组匹配，自动派发工单
"""
import os
import json
import logging

from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage, SystemMessage

logger = logging.getLogger(__name__)

ASSIGN_PROMPT = """你是智能派单专家。请根据工单信息，决定将工单派发给哪个技能组。

技能组说明：
- IT支持组：处理登录问题、系统故障、网络异常等IT相关问题
- 维修工程师：处理设备硬件故障、死机、蓝屏等物理设备问题
- 财务组：处理退款、账单、支付等财务相关问题
- 客服组：处理产品咨询、投诉、建议等客户服务问题

工单信息：
{ticket_info}

请以 JSON 格式输出：
{{
    "skill_group": "目标技能组",
    "priority": "处理优先级（高/中/低）",
    "reason": "派单理由",
    "estimated_time": "预计处理时间"
}}
"""


class AssignAgent:
    """智能派单 Agent"""

    SKILL_GROUPS = ["IT支持组", "维修工程师", "财务组", "客服组"]

    # 规则映射（优先使用规则，LLM 作为兜底）
    CATEGORY_TO_GROUP = {
        "登录问题": "IT支持组",
        "系统故障": "IT支持组",
        "网络异常": "IT支持组",
        "设备故障": "维修工程师",
        "财务问题": "财务组",
    }

    def __init__(self, ticket_tools=None):
        self.ticket_tools = ticket_tools
        self.llm = ChatOpenAI(
            model=os.getenv("LLM_MODEL", "deepseek-chat"),
            base_url=os.getenv("LLM_BASE_URL", "https://api.deepseek.com"),
            api_key=os.getenv("DEEPSEEK_API_KEY"),
            temperature=0.1,
            max_tokens=512,
        )

    def assign(self, ticket: dict) -> dict:
        """
        派单决策
        返回: {"skill_group": str, "priority": str, "reason": str, "assigned": bool}
        """
        # Step 1: 规则匹配
        category = ticket.get("problem_type", "") or ticket.get("category", "")
        rule_group = self.CATEGORY_TO_GROUP.get(category)

        if rule_group:
            result = {
                "skill_group": rule_group,
                "priority": ticket.get("urgency", "中"),
                "reason": f"根据问题类型「{category}」规则路由到 {rule_group}",
                "assigned": True,
            }
        else:
            # Step 2: LLM 决策
            result = self._llm_assign(ticket)

        # Step 3: 执行派单
        ticket_id = ticket.get("ticket_id")
        if ticket_id and self.ticket_tools and result.get("assigned"):

                ticket_id=ticket_id,
                skill_group=result["skill_group"],
                reason=result["reason"],
            )
            result["assign_result"] = assign_result

        logger.info(f"派单决策: {ticket_id} → {result['skill_group']}")
        return result

    def _llm_assign(self, ticket: dict) -> dict:
        """LLM 派单决策"""
        try:
            prompt = ASSIGN_PROMPT.format(
                ticket_info=json.dumps(ticket, ensure_ascii=False, indent=2)
            )
            response = self.llm.invoke([HumanMessage(content=prompt)])
            result = self._parse_json(response.content)
            result["assigned"] = True
            return result
        except Exception as e:
            logger.error(f"LLM 派单失败: {e}")
            return {
                "skill_group": "客服组",  # 默认兜底
                "priority": "中",
                "reason": f"LLM 决策失败，默认分配到客服组: {e}",
                "assigned": True,
            }

    def _parse_json(self, text: str) -> dict:
        """解析 JSON"""
        import re
        json_match = re.search(r'```(?:json)?\s*(\{.*?\})\s*```', text, re.DOTALL)
        if json_match:
            text = json_match.group(1)
        else:
            json_match = re.search(r'\{.*\}', text, re.DOTALL)
            if json_match:
                text = json_match.group(0)
        try:
            return json.loads(text)
        except json.JSONDecodeError:
            return {"skill_group": "客服组", "priority": "中", "reason": "解析失败"}
```

## 第 22 步：`agents/knowledge_agent.py` —— 知识沉淀 Agent（闭环最后一环）

**角色**：工单解决后，把"问题 + 排查过程 + 解决方案"自动总结成一条知识，去重后写进知识库。这样下次遇到同类问题，检索就能直接命中——系统越用越聪明，形成**闭环**。

**为什么排这里**：它依赖 ES 和 Embedding（都是可注入的），是业务闭环的收尾。

**设计要点**：
- `settle()` 主流程四步，对照注释看：
  1. **前置判断**：只有 `status == "closed"`（已关闭）的工单才沉淀；
  2. `_summarize`：LLM 把工单提炼成 `{title, content, solution, category, tags}`；
  3. **向量化 + 去重**：给知识生成向量，用 ES knn 找最近邻，若相似度 ≥ 0.92（`dedup_threshold`）判定重复，拒绝入库——**避免知识库被重复内容污染**；
  4. 入库：附上来源工单号、质量分、创建时间，`es.index` 写入。
- `_evaluate_quality()`：质量分 = 基础 0.8 + 有解决方案 +0.1，有满意度评分则映射到 0.5~1.0。这是"知识质量评估"的朴素实现（呼应第 2 步配置的 `min_quality_score`）。
- 依赖全是可选的（`es_client=None, embedder=None`）：没有 ES/Embedding 也能返回"提炼好的知识"（只是不入库、不向量化）。

```python
        es_client: Elasticsearch 客户端
        embedder: DashScopeEmbedding 实例
        """
        self.es = es_client
        self.embedder = embedder
        self.llm = ChatOpenAI(
            model=os.getenv("LLM_MODEL", "deepseek-chat"),
            base_url=os.getenv("LLM_BASE_URL", "https://api.deepseek.com"),
            api_key=os.getenv("DEEPSEEK_API_KEY"),
            temperature=0.3,
            max_tokens=2048,
        )
        self.dedup_threshold = 0.92

    def settle(self, ticket: dict) -> dict:
        """
        将已关闭工单沉淀为知识
        流程：LLM摘要 → 向量化 → 去重检测 → 入库
        """
        if ticket.get("status") != "closed":
            return {"success": False, "message": "工单未关闭，暂不沉淀"}

        # Step 1: LLM 提炼知识
        knowledge = self._summarize(ticket)
        if not knowledge:
            return {"success": False, "message": "知识提炼失败"}

        # Step 2: 向量化
        if self.embedder:
            text_for_vec = f"{knowledge.get('title', '')} {knowledge.get('content', '')} {knowledge.get('solution', '')}"
            knowledge["content_vector"] = self.embedder.embed_text(text_for_vec)

        # Step 3: 去重检测
        if self.es and self.embedder:
            duplicate = self._check_duplicate(knowledge["content_vector"])
            if duplicate:
                return {
                    "success": False,
                    "message": f"检测到重复知识（相似度>{self.dedup_threshold}），已有条目: {duplicate}",
                    "duplicate": True,
                }

        # Step 4: 入库
        knowledge["source_ticket"] = ticket.get("ticket_id")
        knowledge["quality_score"] = self._evaluate_quality(ticket)
        knowledge["create_date"] = datetime.now().isoformat()

        if self.es:
            try:
                resp = self.es.index(index="knowledge_base", document=knowledge)
                knowledge["kb_id"] = resp["_id"]
                logger.info(f"知识沉淀成功: {knowledge['title']} (kb_id: {resp['_id']})")
                return {"success": True, "kb_id": resp["_id"], "knowledge": knowledge}
            except Exception as e:
                logger.error(f"知识入库失败: {e}")
                return {"success": False, "message": f"入库失败: {e}"}

        return {"success": True, "knowledge": knowledge}

    def _summarize(self, ticket: dict) -> dict:
        """LLM 提炼知识摘要"""
        try:
            prompt = SUMMARIZE_PROMPT.format(
                ticket_info=json.dumps(ticket, ensure_ascii=False, indent=2)
            )
            response = self.llm.invoke([HumanMessage(content=prompt)])
            return self._parse_json(response.content)
        except Exception as e:
            logger.error(f"知识摘要失败: {e}")
            return None

    def _check_duplicate(self, vector: list) -> str:
        """向量去重检测"""
        if not self.es or not vector:
            return None
        try:
            resp = self.es.search(
                index="knowledge_base",
                body={
                    "knn": {
                        "field": "content_vector",
                        "query_vector": vector,
                        "k": 1,
                        "num_candidates": 10,
                    },
                    "_source": ["title"],
                },
            )
            hits = resp.get("hits", {}).get("hits", [])
            if hits and hits[0]["_score"] >= self.dedup_threshold:
                return hits[0]["_source"].get("title", hits[0]["_id"])
        except Exception as e:
            logger.warning(f"去重检测失败: {e}")
        return None

    def _evaluate_quality(self, ticket: dict) -> float:
        """评估知识质量（基于工单满意度和解决时长）"""
        score = 0.8  # 基础分

        # 有解决方案加分
        if ticket.get("resolution"):
            score += 0.1

        # 有满意度评分
        satisfaction = ticket.get("satisfaction")
        if satisfaction:
            score = satisfaction * 0.5 + 0.5  # 映射到 0.5-1.0

        return min(score, 1.0)

    def _parse_json(self, text: str) -> dict:
        """解析 JSON"""
        import re
        json_match = re.search(r'```(?:json)?\s*(\{.*?\})\s*```', text, re.DOTALL)
        if json_match:
            text = json_match.group(1)
        else:
            json_match = re.search(r'\{.*\}', text, re.DOTALL)
            if json_match:
                text = json_match.group(0)
        try:
            return json.loads(text)
        except json.JSONDecodeError:
            return {}
```

## 第 23 步：`agents/graph.py` —— LangGraph 多 Agent 编排（大脑总指挥）

**角色**：前面 5 个 Agent 各自为战，谁先谁后、什么条件下走哪条路？这个文件用 **LangGraph** 把 5 个 Agent + 工具编排成一张"状态机图"：定义节点（每个 Agent 是一个节点）、定义边（节点之间怎么流转）、定义条件路由（根据状态决定下一步）。这是整个系统的"大脑"。

**为什么排这里**：它 `import` 了第 18~22 步的全部 Agent 和第 16 步的工具，是 Agent 层的"总装车间"，必须最后读。

**设计要点**（这是全文最重要的一课，慢慢读）：

1. **状态定义 `AgentState`（TypedDict）**：整个图共享一份"状态"，节点之间靠读写这份状态传递数据。`user_input / intent / slots / ticket_id / response ...` 就是贯穿全程的"上下文黑板"。

2. **`_build_graph()` 搭图**：
   - `workflow.add_node("名字", 处理函数)` 注册节点；
   - `set_entry_point("intent_recognition")` 设入口；
   - `add_conditional_edges("当前节点", 路由函数, {返回值的映射})` 实现**条件分支**——路由函数返回字符串，映射表决定跳到哪个节点；
   - `add_edge("A", "B")` 实现**固定流转**（A 完事必去 B）；
   - `workflow.compile()` 编译成可运行的图。

3. **路由逻辑（核心业务规则）**：
   - `_route_after_intent`：意图是 create_ticket → 去槽位填充；query_ticket → 去查工单；search_knowledge → 去搜知识；其他（assign/chitchat）→ 直接生成回复。
   - `_route_after_slot`：槽位齐全 → 去创建工单；不全 → 生成追问回复。

4. **节点函数都是"纯状态转换"**：输入 `state`，返回一个**局部更新字典**（只包含本节点要改的字段），LangGraph 自动合并回全局状态。注意 `_create_ticket_node` 里调用的是 `self.ticket_tools.create_ticket`（工具），`_query_ticket_node` 里调用的是 `self.ticket_agent.process`（Agent）——**编排器把 Agent 和工具都当"节点"统一调度**。

5. **`run()` 公共接口**：构造初始状态 → `self.graph.invoke(initial_state)` 跑完整张图 → 取最终状态里的关键字段返回。这是给上层（第 25 步的问答页）调用的入口。

6. **`settle_ticket()`**：单独暴露"知识沉淀"能力（工单关闭后外部直接调），不走完整图。

```python
"""
多智能体协同编排（LangGraph）
编排流程：意图识别 → 槽位填充 → 工具调用 → 派单 → 知识沉淀
"""
import os
import json
import logging
from typing import TypedDict, Annotated, Literal
from datetime import datetime

from langgraph.graph import StateGraph, END

from agents.intent_agent import IntentAgent
from agents.slot_filling_agent import SlotFillingAgent
from agents.ticket_agent import TicketAgent
from agents.assign_agent import AssignAgent
from agents.knowledge_agent import KnowledgeAgent
from tools.function_tools import TicketTools

logger = logging.getLogger(__name__)


# ========== 状态定义 ==========

class AgentState(TypedDict):
    """多 Agent 协同状态"""
    user_input: str                    # 用户输入
    intent: str                        # 识别的意图
    intent_confidence: float           # 意图置信度
    slots: dict                        # 已填充的槽位
    slots_complete: bool               # 槽位是否完整
    follow_up: str                     # 追问消息
    response: str                      # 最终回复
    ticket_id: str                     # 工单ID
    tool_calls: list                   # 工具调用记录
    assign_result: dict                # 派单结果
    knowledge_result: dict             # 知识沉淀结果
    step: str                          # 当前步骤


# ========== 节点函数 ==========

class MultiAgentOrchestrator:
    """多智能体协同编排器"""

    def __init__(self, es_client=None, embedder=None, search_pipeline=None):
        # 初始化工具
        self.ticket_tools = TicketTools(es_client=es_client, search_pipeline=search_pipeline)

        # 初始化各 Agent
        self.intent_agent = IntentAgent()
        self.slot_agent = SlotFillingAgent()
        self.ticket_agent = TicketAgent(self.ticket_tools)
        self.assign_agent = AssignAgent(self.ticket_tools)
        self.knowledge_agent = KnowledgeAgent(es_client=es_client, embedder=embedder)

        # 构建 LangGraph
        self.graph = self._build_graph()

    def _build_graph(self) -> StateGraph:
        """构建多 Agent 协同图"""
        workflow = StateGraph(AgentState)

        # 添加节点
        workflow.add_node("intent_recognition", self._intent_node)
        workflow.add_node("slot_filling", self._slot_node)
        workflow.add_node("create_ticket", self._create_ticket_node)
        workflow.add_node("query_ticket", self._query_ticket_node)
        workflow.add_node("search_knowledge", self._search_knowledge_node)
        workflow.add_node("assign_ticket", self._assign_node)
        workflow.add_node("settle_knowledge", self._settle_knowledge_node)
        workflow.add_node("generate_response", self._response_node)

        # 入口
        workflow.set_entry_point("intent_recognition")

        # 条件路由
        workflow.add_conditional_edges(
            "intent_recognition",
            self._route_after_intent,
            {
                "slot_filling": "slot_filling",
                "query_ticket": "query_ticket",
                "search_knowledge": "search_knowledge",
                "generate_response": "generate_response",
            },
        )

        workflow.add_conditional_edges(
            "slot_filling",
            self._route_after_slot,
            {
                "create_ticket": "create_ticket",
                "follow_up": "generate_response",
            },
        )

        workflow.add_edge("create_ticket", "assign_ticket")
        workflow.add_edge("assign_ticket", "generate_response")
        workflow.add_edge("query_ticket", "generate_response")
        workflow.add_edge("search_knowledge", "generate_response")
        workflow.add_edge("settle_knowledge", END)
        workflow.add_edge("generate_response", END)

        return workflow.compile()

    # ========== 节点实现 ==========

    def _intent_node(self, state: AgentState) -> dict:
        """意图识别节点"""
        result = self.intent_agent.recognize(state["user_input"])
        return {
            "intent": result["intent"],
            "intent_confidence": result["confidence"],
            "step": "intent",
        }

    def _slot_node(self, state: AgentState) -> dict:
        """槽位填充节点"""
        result = self.slot_agent.fill(state["user_input"])
        return {
            "slots": result["slots"],
            "slots_complete": result["complete"],
            "follow_up": result["follow_up"],
            "step": "slot_filling",
        }

    def _create_ticket_node(self, state: AgentState) -> dict:
        """创建工单节点"""
        slots = state.get("slots", {})
        result = self.ticket_tools.create_ticket(
            problem_type=slots.get("problem_type", "其他"),
            description=slots.get("description", ""),
            product=slots.get("product"),
            urgency=slots.get("urgency", "中"),
        )
        return {
            "ticket_id": result.get("ticket_id"),
            "tool_calls": [{"tool": "create_ticket", "result": result}],
            "step": "create_ticket",
        }

    def _query_ticket_node(self, state: AgentState) -> dict:
        """查询工单节点"""
        result = self.ticket_agent.process(state["user_input"])
        return {
            "response": result["response"],
            "tool_calls": result["tool_calls"],
            "step": "query_ticket",
        }

    def _search_knowledge_node(self, state: AgentState) -> dict:
        """知识检索节点"""
        result = self.ticket_tools.search_knowledge(state["user_input"])
        if result.get("success"):
            results_text = "\n".join(
                f"- [{r['title']}] {r['content'][:100]}"
                for r in result.get("results", [])[:5]
            )
            response = f"为您找到以下相关知识：\n{results_text}"
        else:
            response = "抱歉，未找到相关知识。"
        return {
            "response": response,
            "step": "search_knowledge",
        }

    def _assign_node(self, state: AgentState) -> dict:
        """派单节点"""
        ticket_id = state.get("ticket_id")
        if not ticket_id:
            return {"step": "assign", "assign_result": {"success": False}}

        ticket_info = {
            "ticket_id": ticket_id,
            "problem_type": state.get("slots", {}).get("problem_type"),
            "urgency": state.get("slots", {}).get("urgency", "中"),
        }
        result = self.assign_agent.assign(ticket_info)
        return {
            "assign_result": result,
            "step": "assign",
        }

    def _settle_knowledge_node(self, state: AgentState) -> dict:
        """知识沉淀节点"""
        ticket_id = state.get("ticket_id")
        if not ticket_id:
            return {"step": "settle_knowledge"}

        ticket = {
            "ticket_id": ticket_id,
            "status": "closed",
            **state.get("slots", {}),
        }
        result = self.knowledge_agent.settle(ticket)
        return {
            "knowledge_result": result,
            "step": "settle_knowledge",
        }

    def _response_node(self, state: AgentState) -> dict:
        """生成最终回复节点"""
        if state.get("response"):
            return {"step": "response"}

        # 根据状态生成回复
        intent = state.get("intent", "")
        ticket_id = state.get("ticket_id", "")
        assign_result = state.get("assign_result", {})

        if intent == "create_ticket" and ticket_id:
            group = assign_result.get("skill_group", "未分配")
            response = (
                f"✅ 工单已创建成功！\n"
                f"工单号：{ticket_id}\n"
                f"已派发给：{group}\n"
                f"我们会尽快处理您的问题。"
            )
        elif state.get("follow_up"):
            response = state["follow_up"]
        else:
            response = "已收到您的请求，正在处理中..."

        return {"response": response, "step": "response"}

    # ========== 路由函数 ==========

    def _route_after_intent(self, state: AgentState) -> str:
        """意图识别后的路由"""
        intent = state.get("intent", "chitchat")
        if intent == "create_ticket":
            return "slot_filling"
        elif intent == "query_ticket":
            return "query_ticket"
        elif intent == "search_knowledge":
            return "search_knowledge"
        else:
            return "generate_response"

    def _route_after_slot(self, state: AgentState) -> str:
        """槽位填充后的路由"""
        if state.get("slots_complete"):
            return "create_ticket"
        else:
            return "follow_up"  # 追问用户补充信息

    # ========== 公共接口 ==========

    def run(self, user_input: str) -> dict:
        """
        运行多 Agent 协同流程
        返回最终状态
        """
        initial_state = {
            "user_input": user_input,
            "intent": "",
            "intent_confidence": 0.0,
            "slots": {},
            "slots_complete": False,
            "follow_up": None,
            "response": "",
            "ticket_id": None,
            "tool_calls": [],
            "assign_result": {},
            "knowledge_result": {},
            "step": "",
        }

        final_state = self.graph.invoke(initial_state)
        return {
            "response": final_state.get("response", ""),
            "intent": final_state.get("intent", ""),
            "ticket_id": final_state.get("ticket_id"),
            "slots": final_state.get("slots", {}),
            "assign_result": final_state.get("assign_result", {}),
            "step": final_state.get("step", ""),
        }

    def settle_ticket(self, ticket: dict) -> dict:
        """单独调用知识沉淀流程"""
        initial_state = {
            "user_input": "",
            "intent": "settle",
            "intent_confidence": 1.0,
            "slots": {},
            "slots_complete": True,
            "follow_up": None,
            "response": "",
            "ticket_id": ticket.get("ticket_id"),
            "tool_calls": [],
            "assign_result": {},
            "knowledge_result": {},
            "step": "",
        }
        # 直接走知识沉淀节点
        result = self.knowledge_agent.settle(ticket)
        return result
```

- LangGraph 的三个核心概念：**State（共享状态）、Node（节点=处理函数）、Edge（边=流转）+ 条件路由**。
- 节点函数"返回局部更新字典"的约定。
- 整条业务流的走向：`意图识别 → (槽位填充 → 创建工单 → 派单) / 查工单 / 搜知识 → 生成回复 → 结束`，知识沉淀作为独立分支。

## 第 25 步：`web/pages/chat.py` —— 智能问答页（大脑的前台）

**角色**：用户在聊天框里打字，这里把输入丢给第 23 步的 `MultiAgentOrchestrator`，把最终回复显示出来。这是整个系统"端到端"能力的入口。

**为什么排这里**：它依赖第 23 步的编排器。

**设计要点**：
- `st.session_state.messages` 保存聊天历史（Streamlit 每次交互都会重跑脚本，session_state 是"跨重跑保持状态"的机制）。
- `st.chat_input` / `st.chat_message` 是 Streamlit 的聊天组件。
- 关键在 `render()` 里的 try/except：先 `from agents.graph import MultiAgentOrchestrator`（**惰性导入**，在 `with st.spinner` 里），再 `run(prompt)`。捕获 `ImportError`（依赖没装，提示用户 pip install）和通用 `Exception`（显示错误）。**前端对后端依赖的容错**。

```python
"""智能问答页面"""
import sys
from pathlib import Path
sys.path.insert(0, str(Path(__file__).parent.parent.parent))

import streamlit as st


def render():
    st.markdown("## 💬 智能问答")
    st.caption("报告问题自动创建工单 · 查询进度 · 搜索解决方案")
    
    # 初始化会话状态
    if "messages" not in st.session_state:
        st.session_state.messages = [
            {"role": "assistant", "content": "你好！我是智能工单助手。\n\n你可以：\n- 📝 **报告问题** — 自动创建工单并派发\n- 🔍 **查询工单** — 查看处理进度\n- 📚 **搜索知识** — 查找历史解决方案\n- 👤 **转人工** — 转接专业工程师"}
        ]
    
    # 显示历史
    for msg in st.session_state.messages:
        with st.chat_message(msg["role"]):
            st.markdown(msg["content"])
    
    # 输入框
    if prompt := st.chat_input("描述你的问题..."):
        st.session_state.messages.append({"role": "user", "content": prompt})
        with st.chat_message("user"):
            st.markdown(prompt)
        
        with st.chat_message("assistant"):
            with st.spinner("思考中..."):
                try:
                    from agents.graph import MultiAgentOrchestrator
                    result = MultiAgentOrchestrator().run(prompt)
                    response = result.get("response", "已收到您的请求。")
                except ImportError:
                    response = f"收到：「{prompt}」\n\n> Agent 依赖未安装，请运行 `pip install -r requirements.txt`"
                except Exception as e:
                    response = f"处理出错：{e}"
            
            st.markdown(response)
            st.session_state.messages.append({"role": "assistant", "content": response})
    
    # 清空按钮
    if st.sidebar.button("🗑️ 清空对话"):
        st.session_state.messages = st.session_state.messages[:1]
        st.rerun()
```

- Streamlit 聊天界面的写法（session_state + chat_input + chat_message）。
- 惰性导入 + 异常捕获，保证后端没就绪时前端也能优雅提示。

## 第 27 步：`web/pages/knowledge.py` —— 知识检索页（检索层的前台）

**角色**：给用户一个搜索框，输入问题，调用第 15 步的混合检索管道，把结果卡片化展示（含解决方案、类别、标签、分数）。

**为什么排这里**：它依赖第 15 步的 `HybridSearchPipeline`。

**设计要点**：

## 附录 A：依赖关系图（谁依赖谁）

## 附录 B：一条工单的完整旅行（把 28 步串起来）

假设用户在"智能问答"页输入：**"我的服务器一直返回 502 错误，帮我创建工单"**：

1. `web/pages/chat.py` 拿到输入，调 `MultiAgentOrchestrator().run(...)`（第 25 步）。
2. `agents/graph.py` 的图启动，先进 `intent_recognition` 节点 → `IntentAgent.recognize` 判出 `create_ticket`（第 18 步）。
3. 条件路由 `_route_after_intent` 发现是 create_ticket → 跳 `slot_filling` 节点 → `SlotFillingAgent.fill` 抽出 problem_type="系统故障"、description=...、urgency="高"（第 19 步）。
4. 槽位齐全 → `_route_after_slot` 跳 `create_ticket` 节点 → `TicketTools.create_ticket` 生成工单号、写内存（有 ES 则落库）（第 16 步）。
5. 固定边 `create_ticket → assign_ticket` → `AssignAgent.assign` 按"系统故障"规则映射到"IT支持组"，并执行 `assign_engineer` 落库（第 21 步）。
6. 固定边 `assign_ticket → generate_response` → 拼出"工单已创建，已派发给 IT支持组"（第 23 步）。
7. 回到 `web/pages/chat.py` 显示给用户。
8. （工单解决后）外部调 `settle_ticket` → `KnowledgeAgent.settle` 走"LLM 摘要 → 向量化 → 去重 → 入库"（第 22 步），知识沉淀进库。
9. 下次有人搜"502"，`web/pages/knowledge.py` → `HybridSearchPipeline.search`（第 15 步）就能直接命中这条知识。
